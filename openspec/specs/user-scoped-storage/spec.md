# user-scoped-storage Specification

## Purpose

为单设备上的登录用户建立收敛且受保护的当前会话，并提供独立、可验证的本地物理存储命名空间，使数据库、偏好、文件、内存缓存和后台任务在退出、失效、换号及进程重建后都不会泄露会话秘密或跨用户读取、覆盖和恢复。

## Requirements

### Requirement: 稳定且完整的用户归属
系统 SHALL 使用 `companyId`、`accountId` 和 `userId` 的完整组合作为 `UserScopeKey`；Token、角色、显示名和手机号变化不得改变该归属，任一归属字段不同 MUST 视为不同用户作用域。文件系统名称 SHALL 由版本化规范输入的稳定加密摘要生成，不得直接暴露原始用户标识。

#### Scenario: 登录后解析用户作用域
- **WHEN** 登录成功并取得包含 `companyId`、`accountId` 和 `userId` 的登录结果
- **THEN** 系统产生唯一的当前用户作用域和稳定的不透明命名空间标识
- **AND** 后续用户数据操作只能通过该作用域取得存储访问权

#### Scenario: Token 刷新不切换存储
- **WHEN** 当前用户仅更新 Token 或非归属资料
- **THEN** 系统继续使用原用户作用域和同一组物理存储文件

#### Scenario: 任一归属字段变化
- **WHEN** 新会话的 `companyId`、`accountId` 或 `userId` 任一项与当前作用域不同
- **THEN** 系统将其识别为账号切换，并禁止复用旧作用域的数据、文件和任务

### Requirement: 当前用户会话只公开必要的非秘密信息
系统 SHALL 通过单一不可变的当前用户视图向 UI、普通业务功能和生命周期观察者提供完整 `UserScopeKey` 及姓名、头像、角色、性别等必要资料。该公开视图 MUST NOT 包含 Token、身份证号或完整登录响应；登录成功 UI 状态、页面状态、导航参数和普通业务缓存同样不得携带这些秘密。Token 只能在认证请求组装边界使用，当前用户身份证号只能在明确需要实名信息的业务边界使用。

#### Scenario: UI 观察当前用户
- **WHEN** 页面或 ViewModel 观察已登录会话并显示姓名、头像或角色
- **THEN** 调用方取得同一个安全的当前用户视图
- **AND** 该视图无法读取 Token、身份证号或完整持久会话

#### Scenario: 登录页面收到成功结果
- **WHEN** 登录请求成功且会话已经安全激活
- **THEN** 登录 UI 只收到可用于导航的成功状态
- **AND** 不把完整登录结果、Token 或身份证号放入 UI 状态

#### Scenario: 网络请求需要认证
- **WHEN** 网络层为当前活动会话组装认证请求
- **THEN** Token 只在请求组装边界的短期快照中使用
- **AND** Token 不通过公开会话状态、日志、缓存键或调用方返回值暴露

#### Scenario: 实名业务需要当前用户身份证号
- **WHEN** 人脸建档等明确的实名业务需要当前用户姓名和身份证号
- **THEN** 负责该业务的数据边界在内部完成实名请求组装
- **AND** 页面状态、导航参数和普通 Feature 调用方不会获得原始身份证号

### Requirement: 当前会话持久化具有单一原子且受保护的事实来源
系统 SHALL 以单一原子持久化记录作为当前会话的唯一事实来源，并在同一记录中保存格式版本、`PENDING/ACTIVE` 阶段、`sessionEpoch`、当前用户、Token 和当前用户身份证号。记录整体 MUST 使用应用绑定且不可导出的密钥进行静态加密，并 MUST 排除在备份之外；阶段与会话载荷不得由两个可独立提交的存储分别维护。该记录不得保存订单、提醒、图片记录、系统业务配置或多个用户的历史业务数据。

#### Scenario: 登录期间进程被终止
- **WHEN** 新登录会话处于 `PENDING` 或切换到 `ACTIVE` 的过程中进程被终止
- **THEN** 磁盘上只存在一个阶段与完整会话载荷一致的原子记录
- **AND** 系统不会恢复出“已激活但缺少身份或秘密”的部分会话

#### Scenario: 恢复有效活动会话
- **WHEN** 进程启动并成功解密、解析且核对一个 `ACTIVE` 当前会话记录
- **THEN** 系统使用其中的完整作用域验证并打开唯一目标用户命名空间
- **AND** 只在用户存储就绪后公开已登录状态

#### Scenario: 会话记录无法安全解密
- **WHEN** 加密密钥失效、密文损坏、字段缺失或会话归属无法核对
- **THEN** 系统删除或隔离不可用记录并进入登出状态
- **AND** 不读取旧明文、不扫描最近用户文件且不恢复任何用户任务

#### Scenario: 退出时删除当前会话记录
- **WHEN** 当前用户手动退出、Token 失效或切换账号
- **THEN** 系统删除旧的加密会话记录并清除对应内存秘密
- **AND** 旧 Token 和当前用户身份证号无法从会话存储恢复

### Requirement: 设备数据、用户数据和会话数据分类
系统 MUST 明确区分设备级、用户级和会话级存储。隐私同意、设备实例 ID、设备兼容性标记、上次登录手机号和应用更新状态 SHALL 保持设备级；订单及本地状态、业务图片记录、系统业务配置、待恢复服务提醒和用户文件 SHALL 归属用户；安全当前用户视图、访问令牌、当前用户身份证号、临时厂商凭据和进程内业务缓存 SHALL 归属当前会话。当前会话持久化只能保存唯一活动或切换中的会话，不得充当多用户业务数据容器；上次登录手机号不得作为当前用户作用域或认证依据。本分类约束新版本写入后的正常生命周期，不构成对任何 legacy 值的兼容或迁移承诺。

#### Scenario: 退出后保留设备级设置
- **WHEN** 用户退出登录或会话失效
- **THEN** 隐私同意、设备实例 ID、兼容性标记、上次登录手机号和应用更新状态保持不变
- **AND** 上一用户的业务数据不会作为下一用户的数据返回

#### Scenario: 清除会话级秘密
- **WHEN** 当前会话退出、失效或切换到其他用户
- **THEN** 系统清除旧会话的加密记录、Token、当前用户身份证号、临时厂商凭据和进程内业务缓存

#### Scenario: 未登录时发现存储
- **WHEN** 应用没有可解码且归属字段完整的当前会话
- **THEN** 系统不得根据最近文件、最近用户或目录扫描自动选择任何用户命名空间

### Requirement: 每个用户使用独立物理存储命名空间
每个 `UserScopeKey` SHALL 对应独立的 Room 数据库文件、独立的用户级 DataStore 文件集合和独立的受管业务文件根目录。命名空间 MUST 保存可核对的完整归属元数据；打开数据库、DataStore 或文件目录前 MUST 验证元数据与请求作用域一致。用户业务数据不得继续写入固定名称的全局数据库、全局业务偏好文件或共享业务目录。

#### Scenario: 两个用户拥有相同订单号
- **GIVEN** 用户 A 和用户 B 的服务端数据包含相同 `orderId`
- **WHEN** 两个用户先后在同一设备使用应用
- **THEN** 两份订单、本地状态、项目和图片记录写入不同的数据库文件与文件根目录
- **AND** 用户 B 无法读取、更新或删除用户 A 的记录及文件

#### Scenario: 同一用户再次登录
- **WHEN** 完整复合身份相同的用户再次登录且其命名空间元数据有效
- **THEN** 系统重新连接该用户原有的独立命名空间，而不是创建随机新文件或选择其他用户文件

#### Scenario: 命名空间元数据不匹配
- **WHEN** 文件名摘要指向的命名空间元数据与当前 `UserScopeKey` 不一致、缺失或损坏
- **THEN** 系统 fail closed，不读取该命名空间、不把其中数据归给当前用户，并进入可安全重建当前用户缓存的状态

### Requirement: 用户存储实例由单一注册表管理
系统 SHALL 通过进程级用户存储注册表创建和访问用户命名空间，不得在 Repository、Worker、Receiver 或页面中临时构造数据库或 DataStore。每个物理 Room 数据库在活动期间 MUST 只有一个受管句柄，每个物理 DataStore 文件在同一进程内 MUST 始终只有一个受管实例；固定全局数据库的 DAO 不得作为跨用户单例注入。

#### Scenario: 多个调用方并发访问当前用户
- **WHEN** 多个 Repository 或后台组件同时请求当前用户的同一数据库或 DataStore
- **THEN** 注册表向它们提供同一受管实例和同一代访问租约，不重复创建物理文件实例

#### Scenario: 账号切换释放旧访问权
- **WHEN** 当前作用域从用户 A 切换到用户 B
- **THEN** 系统先阻止新的 A 用户操作、撤销 A 的访问租约、停止其观察流并关闭其 Room 句柄
- **AND** A 的 DataStore 实例不再提供给活动调用方，B 的命名空间验证完成后才开放业务访问

#### Scenario: 旧异步写入延迟完成
- **WHEN** 用户 A 的异步操作在存储代次已经切换后尝试提交
- **THEN** 注册表拒绝该提交，结果不得写入用户 A 或用户 B 的活动命名空间

### Requirement: 未登录与切换中的用户存储访问 fail closed
所有用户业务读取、写入、更新、删除和观察操作 SHALL 在当前有效命名空间租约内执行。没有已解析登录作用域、命名空间正在切换或租约已失效时，用户业务存储 MUST 返回明确的未认证、切换中或过期失败，不得回退到全局数据库、最近用户或无归属数据。

#### Scenario: 未登录访问用户数据
- **WHEN** Receiver、Worker、Repository 或页面在会话未解析或已登出时请求用户业务数据
- **THEN** 操作返回明确失败或空的未认证结果，不读取任何历史用户文件

#### Scenario: 观察流发生账号切换
- **WHEN** 一个用户数据观察流存活期间当前作用域切换
- **THEN** 旧观察流终止且不再向新会话发射，调用方必须在新作用域就绪后重新订阅

#### Scenario: 切换期间页面发起写入
- **WHEN** 页面在旧命名空间已撤销且新命名空间尚未就绪时提交用户业务数据
- **THEN** 写入以可识别的切换中状态失败，不排队到未确定的用户空间

### Requirement: 用户文件与数据库记录拥有相同命名空间
系统 SHALL 将持久业务图片和其他用户文件放入当前用户的受管文件根目录，并确保数据库记录只能引用同一命名空间内的相对路径或受验证句柄。删除用户 A 的记录 MUST NOT 删除用户 B 的文件，即使订单号或文件用途相同；路径解析 MUST 防止逃逸到命名空间根目录之外。

#### Scenario: 不同用户保存同用途图片
- **WHEN** 用户 A 和用户 B 分别为相同订单号保存服务照片或人脸相关文件
- **THEN** 文件路径位于不同用户命名空间，查询和清理只能作用于当前归属

#### Scenario: 退出时清理敏感临时文件
- **WHEN** 用户退出、会话失效或切换账号
- **THEN** 系统清除旧会话的人脸、拍摄和上传临时文件，同时不会删除任何用户的持久业务文件

#### Scenario: 文件路径尝试越界
- **WHEN** 持久记录或调用方提供绝对路径、父目录跳转或指向其他用户根目录的路径
- **THEN** 文件存储拒绝解析和访问该路径

### Requirement: 会话切换使用统一存储生命周期
登录、手动退出、服务端 Token 失效和显式账号切换 MUST 使用同一用户存储生命周期。系统 SHALL 将完整新会话原子持久化为 `PENDING`，在报告新会话可用于业务操作前停止旧用户实时能力与后台任务、撤销旧存储租约、清理旧会话数据并验证新命名空间，最后才把同一记录切为 `ACTIVE` 并公开登录状态；本地退出不得因服务端退出失败而被跳过。用户级持久缓存默认保留在其独立命名空间供同一复合身份再次登录使用，但在其他作用域中 MUST 保持关闭且不可访问。

#### Scenario: 切换阶段不公开活动会话
- **WHEN** 新会话记录仍处于 `PENDING` 或目标用户命名空间尚未 Ready
- **THEN** 系统不得向 UI、Repository、Worker 或 Receiver 报告该会话已登录可用
- **AND** 所有用户业务访问保持 fail closed

#### Scenario: 手动退出接口失败
- **WHEN** 用户点击退出且服务端退出请求失败或异常
- **THEN** 系统仍完成本地旧任务停止、租约撤销、会话秘密清理和登出状态持久化

#### Scenario: Token 失效
- **WHEN** 网络层确认当前 Token 失效
- **THEN** 系统执行与手动退出相同的用户存储生命周期，不只删除登录 Token

#### Scenario: 同一用户重新登录
- **WHEN** 已退出用户以相同 `UserScopeKey` 再次登录
- **THEN** 系统可重新使用其有效的持久数据库、DataStore 和持久业务文件
- **AND** 先前的 Token、临时凭据、临时文件和已取消任务不会恢复

### Requirement: 持久后台任务携带并校验用户归属
所有与用户业务相关的 Worker、Alarm、PendingIntent、通知去重记录和开机恢复记录 SHALL 携带完整用户作用域或可验证的作用域摘要，其唯一标识 MUST 同时包含用户作用域和业务标识。任务身份与输入 MUST NOT 包含 Token、身份证号或完整持久会话。执行或恢复前 MUST 与当前登录作用域及当前存储代次精确比较，不匹配时取消或丢弃且不产生用户可见副作用。

#### Scenario: 换号后旧 Worker 到期
- **GIVEN** 用户 A 创建了服务结束 Worker
- **WHEN** 用户 B 登录后该 Worker 到期
- **THEN** Worker 不显示通知、不打开任何用户数据库、不读取或删除用户 B 的同订单记录，并终止旧任务

#### Scenario: 重启后恢复提醒
- **WHEN** 设备重启且当前登录用户作用域已经解析
- **THEN** 系统只打开当前用户命名空间并恢复归属于该完整作用域的未完成提醒
- **AND** 不匹配和无归属的历史记录被删除或忽略

#### Scenario: 相同订单号的任务去重
- **WHEN** 两个用户分别为相同 `orderId` 创建提醒
- **THEN** 两个任务的唯一名称、PendingIntent 和去重记录互不冲突

#### Scenario: 后台任务输入不携带会话秘密
- **WHEN** 系统为当前用户调度 Worker、Alarm、PendingIntent 或通知恢复记录
- **THEN** 其持久输入只包含作用域摘要、会话代次和必要业务标识
- **AND** 不包含 Token、身份证号或可解码的完整会话载荷

### Requirement: 进程内缓存不得跨用户复用
订单详情、系统业务配置、对象存储临时凭据和其他可能受登录身份影响的进程内缓存 MUST 以用户作用域和存储代次作为缓存键，或在作用域离开时同步失效。只使用业务类型、文件夹类型、订单号或厂商 App ID 的缓存键 MUST NOT 被视为用户隔离。

#### Scenario: 换号后请求相同订单
- **WHEN** 用户 A 已缓存订单详情，随后用户 B 登录并请求相同 `orderId`
- **THEN** 系统不得返回用户 A 的内存缓存，必须从用户 B 的命名空间或服务端加载

#### Scenario: 换号后申请上传凭据
- **WHEN** 旧会话已缓存对象存储临时凭据且新用户登录
- **THEN** 新用户不得复用旧凭据，系统为新作用域重新获取或读取其独立缓存

### Requirement: 会话与存储归属在进程恢复时一致
系统 SHALL 在报告登录成功或恢复业务页面前解密并核对唯一当前会话记录、命名空间归属元数据和存储代次。只有 `ACTIVE` 且字段完整、密文有效、作用域与目标命名空间一致的记录才能恢复业务会话；若任一项缺失、损坏或不匹配，系统 MUST fail closed：不暴露旧业务数据、不恢复旧任务，并进入可重新登录或重建当前用户缓存的状态。

#### Scenario: 会话数据损坏
- **WHEN** 持久会话无法解码或缺少完整归属字段
- **THEN** 系统进入登出状态，不选择最近使用的用户命名空间且不恢复任何用户任务

#### Scenario: 会话与命名空间归属不一致
- **WHEN** 进程恢复发现持久会话和目标命名空间的归属元数据不一致
- **THEN** 系统拒绝打开不可可信命名空间，直到当前作用域被安全重建后才允许业务访问

#### Scenario: 进程恢复遇到 PENDING 会话
- **WHEN** 进程启动时唯一当前会话记录处于 `PENDING`
- **THEN** 系统完成安全打开或回滚到登出状态
- **AND** 在恢复完成前不公开已登录状态、不打开其他用户文件也不恢复后台任务

### Requirement: 旧本地状态按确认策略整体冷切换
引入独立用户命名空间的版本 SHALL 在恢复会话、访问业务数据或打开任何用户命名空间前，幂等删除全部已知 legacy 本地状态，包括旧明文 `app_user`、隐私同意、设备实例 ID、登录偏好、设备兼容性与应用更新状态、固定名称的全局 Room 业务数据库及 sidecar、无完整复合归属的业务 SharedPreferences/DataStore、缓存、提醒、任务恢复记录和共享业务文件。系统 MUST NOT 解码、复制、转换、重加密、猜测归属或回退这些旧值；只有全部清理步骤成功后才能提交新的切换完成标记。清理完成后应用 SHALL 处于未同意隐私、未登录且未选择任何用户命名空间的冷启动状态。新建的每用户 Room 数据库 SHALL 继续采用已确认的破坏性 schema 重建策略；服务端数据 SHALL 作为事实来源重新填充，schema 快照和重建测试 MUST 与当前版本一致。

#### Scenario: 删除旧明文会话和全部 legacy 状态
- **GIVEN** 升级前存在可解码或损坏的旧 `app_user` 以及任意旧偏好、数据库、缓存、提醒、任务记录或业务文件
- **WHEN** 应用首次执行独立用户命名空间版本的冷切换
- **THEN** 系统删除全部已知 legacy 状态而不读取其业务载荷、不创建新会话也不选择最近用户命名空间
- **AND** 任一步骤失败时不提交切换完成标记，下次启动从幂等清理继续

#### Scenario: 升级后重新确认隐私并初始化设备标识
- **WHEN** legacy 冷切换已经完成且应用进入登录前流程
- **THEN** 旧隐私同意状态和旧设备实例 ID 均不可用，应用重新展示隐私协议并在同意前禁止访问设备标识或启动受隐私门禁约束的能力
- **AND** 用户重新同意后，系统只按新版本规则初始化后续请求使用的安装级设备标识

#### Scenario: 旧明文当前会话不迁移
- **WHEN** 升级入口发现旧 `app_user` 当前会话
- **THEN** 系统不解码、不迁移、不重加密该值并保持登出状态
- **AND** 只有新的登录请求成功后才能创建新的加密会话记录

#### Scenario: 从旧全局数据库升级
- **WHEN** 应用首次运行独立用户命名空间版本且检测到旧固定名称业务数据库
- **THEN** 系统关闭并删除旧数据库及其 sidecar 文件，不保留旧订单、状态、图片记录或提醒记录
- **AND** 在用户重新登录且完整作用域解析成功前不创建或打开任何用户数据库

#### Scenario: 每用户数据库 schema 不兼容
- **WHEN** 某一用户数据库的 schema 版本无法按支持路径打开
- **THEN** 系统只破坏性重建该用户的数据库，不删除其他用户数据库、DataStore、持久文件或设备级偏好

#### Scenario: 新命名空间重新获取数据
- **WHEN** 新登录成功且当前用户命名空间已经 Ready
- **THEN** 应用从服务端重新加载系统业务配置、订单及其他可恢复业务数据，并只写入该用户的独立数据库、DataStore 与文件目录
- **AND** 重新加载完成前不得读取或展示任何 legacy 值

#### Scenario: 服务端重新获取失败
- **WHEN** 新登录后的系统配置或业务数据重新获取失败
- **THEN** 对应功能进入明确的空态或可重试错误状态
- **AND** 系统不得回退到旧配置、旧缓存、全局存储或其他用户命名空间
