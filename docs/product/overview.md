# LongCare 产品概览

最后核对：2026-09-21（护理错误提示及空值处理已做离线回归；非全部真实业务验收）

## 产品定位

LongCare 是面向长期护理服务执行和客户评估场景的 Android 客户端。应用把登录、订单执行、身份核验、定位、服务照片、计时、NFC 签到签退，以及销售顾问的客户登记和评估流程放在同一套受会话与权限约束的移动端工作流中。

当前产品主链路已经实现。现阶段的主要工作不是补齐基础功能，而是保证生产发布安全、提高关键流程验证深度，并继续把仍位于 `:app` 的业务实现迁入独立 feature。

## 用户角色

| 角色 | 应用入口 | 主要目标 |
|---|---|---|
| 护理服务执行人员 | 普通账号首页 | 查看服务单、完成签到与身份核验、执行护理项目、留存位置和照片、结束服务 |
| 销售顾问 | `userIdentity == 2` 的销售首页 | 管理潜在客户、登记资料与照片、处理提醒、发起表单或设备评估、查看报告 |
| 运营与项目人员 | 使用服务端和客户端留痕结果 | 确保服务过程完整、可追溯，并降低人工补录和异常排查成本 |

账号角色由登录后的用户资料决定，同一安装包在 `HomeRoute` 内选择护理端或销售端体验。

## 核心流程

### 启动、隐私与登录

1. 首次启动先展示隐私同意弹窗；未同意时不继续初始化业务 SDK。
2. 登录页协议默认未勾选，发送验证码和登录都要求用户主动同意。
3. 会话状态决定启动目的地：未解析时显示启动页，已登录进入首页，未登录进入登录页。
4. 首页进入时异步记录设备和网络环境日志；会话失效由全局流程统一退出登录并提示。
5. 启动更新检查由 WorkManager 持久化，发现新版本后显示应用内更新弹窗。

应用内所有 H5（含报告、协议和隐私网页弹窗）共用 `window.NativeBridge.closeWebView()` 关闭接口。
普通网页和报告调用只关闭自身，不代表隐私同意；隐私网页关闭后仍需用户在原生弹窗中明确选择。纯表单 H5 按业务约定以主动关闭进入完成页，设备流程直接在上传后进入结果页，不通过网页返回结果。
桥接接口与信任边界统一见[QLZ/H5 接入契约](../integrations/qlz-sdk.md#检测展示与-h5-关闭契约)。

### 护理服务执行

典型链路由首页、服务计划/记录列表和订单详情发起，并按订单状态串联以下能力：

1. 选择服务单或护理项目。
2. 通过原生 NFC 或支持的外接读卡器完成开始/结束服务所需的读卡流程。
3. 进入身份核验：
   - 服务端已有服务人员登记照时，进入 CameraX + ML Kit 页面，完成单人、姿态和眨眼活体检查后拍照，并调用 `/V1/User/CheckFace` 比对。
   - 服务端没有登记照或查询失败时，进入补录流程并清理旧版遗留的本地人脸文件。
   - 长者留痕照片继续使用标准带水印相机流程。
4. 选择本次服务内容，进入倒计时；服务进行期间按需采集和上报位置、拍摄并上传阶段照片。
5. 选择结束方式、完成签退和服务结果确认，随后返回保留的原首页。签退成功统一清理选中项目和阶段照片，不依赖完成页的特定按钮；接口失败保留重试资料。完成页顶部、系统返回和“完成”均只关闭自身。

倒计时页退出回首页是业务例外：不允许返回前序核验或项目选择重新操作，保持既有流程限制。

具体页面与路由以[页面与路由地图](../architecture/ui-and-screen-map.md)为准。

护理计划详情加载失败时，业务失败显示接口提示（空白时使用本地兜底），连接失败、超时、HTTP 服务异常、响应数据异常分别提示，不再统一归为网络异常；可手动重试或返回。接口明确允许为空的姓名、地址、联系方式等资料不阻断列表/详情加载，缺失值不伪造为真实身份或坐标，原有身份、定位及服务校验保持不变。

### 销售客户与评估

销售账号在首页内使用独立的首页、客户和个人中心导航：

1. 查看最新客户和待办提醒，搜索或选择潜在客户。
2. 登记客户信息；是否残疾为是/否单选，默认否，备注为选填多行文本。填写进入确认时关闭填写页，不再返回修改；提交失败保留确认页、资料和照片供重试，成功后关闭确认页并释放已不用的草稿/照片。相机与预览只是临时工具，返回保留未完成资料。最多添加三张相机照片，复用标准相机、水印、预览和受管文件生命周期。
3. 表单评估使用服务端返回的 `pgUrl`，在应用内 WebView 打开。
4. 设备自动评估先从 LongCare 服务端获取一次性 Token，再请求蓝牙权限，在应用自定义检测页面完成测量与上传。
5. SDK 上传成功后释放会话，以原生评估结果页替换设备/检测进度页，保留其他有效来源页；以客户 ID 和本次 recordId 请求 `POST /V1/Sale/GetCheckResult`，显示 pgResult。100% 采样不会提前跳转，也不自动打开 H5；上传失败留在当前检测页重试。
6. 用户点击“确认并提交评估结果”打开本次结果返回的 pgUrl；报告保持沉浸式，`window.NativeBridge.closeWebView()` 或系统返回只关闭报告并回到结果页。查询失败/结果未就绪时可刷新，无报告地址时按钮不可用，不重新检测、不用旧值或其他接口兜底。纯表单仍在 JS 主动关闭后显示完成页并重新查询客户详情，系统返回回评估入口。所有网页不增加返回结果关联机制，不默认 A 级，不由客户端代替 H5 提交或关闭。
7. 评估表单和报告仅使用 H5 自带标题和返回按钮，不显示重复原生标题栏；白色背景延伸至系统栏形成沉浸式视觉，内容避让状态栏、导航栏/手势区和键盘。离开后恢复原系统栏样式，协议、隐私与普通网页保留原有原生栏。

完整接入约束见 [QLZ SDK 接入](../integrations/qlz-sdk.md)。

信息提交结果页与评估结果页的按钮统一同宽、上下排列：分别为“进行评估 → 确认并返回”和“确认并提交评估结果 → 完成”，返回类操作位于最下方；大字体不切换排列方式，短屏可滚动。设备流程中的通用称呼简化为“设备”，扫描所得真实设备名称保持不变。

“确认并提交评估结果”仅调整评估结果页入口文案，点击仍打开接口返回的 H5，具体提交由 H5 控制，原生端不新增提交请求。客户详情页的“查看评估报告”文案保持不变。

评估表单及报告可调用 `window.NativeBridge.enterUserDetails(pingguuserid)`，使用正整数客户 ID 或数字字符串打开原生客户详情，并关闭当前 H5。同一客户详情来源直接刷新，不重复压入详情；不同客户详情独立查询，不覆盖保留的结果记录。普通网页和隐私弹窗不启用该能力。

销售页面返回和跳转严格区分：顶部返回、系统返回及结果页“完成”只弹出当前页，显示栈中上一有效页，不用固定跳首页替代返回。只有业务结束的填写、确认、检测及 H5 转详情使用替换/移除，已结束页面不再出现在返回路径。

客户详情首次显示或返回前台时查询最新详情，失败可重试；不依赖网页结果回传。客户列表从详情普通返回时保留搜索条件、分页和滚动位置，首次加载或条件变化才从第一页查询；成功空结果也保留，进程恢复丢失数据后重新加载。

## 关键产品规则

- “服务单”是护理服务订单/执行对象，文档中不混用“工单”或“任务单”。
- 标准业务照片只提供应用内相机采集，不提供相册选择；照片经过方向修正、水印、压缩、大小校验和受管文件清理。
- 服务照片上限来自系统配置；缺失或异常配置使用代码中的安全回退策略。
- 持续定位只在当前订单进行中运行。单点上传失败不落库、不排队、不补传；登出、换号、订单成功结束或任务被移除时停止。
- 人脸采集要求单人、合格姿态和完整眨眼序列；最终是否通过由服务端订单比对结果决定。
- 销售登记照片在删除、替换、放弃或提交成功后释放；提交失败时保留以便重试。
- QLZ 的 `appSecret` 只允许存在服务端，Android 客户端只接收一次性检测 Token。
- 隐私同意后长按登录页中央大 Logo 并确认，可进入 NFC/R65C 本地读卡检测；无震动，普通点击不触发，取消则留在登录页，不使用摇动入口。
- 检测支持两种模式选择、结果展示/复制/清空，不上传、不签到、不影响主应用会话；返回保留登录输入。
- 独立助手及其他测试入口已删除；正式业务仍使用的人脸、相机能力保留。

## 当前产品边界与风险

- 未发现缺失的核心护理或销售主链路；仍需通过真机、集成和 smoke 验证降低跨权限、NFC、定位、相机和进程恢复的回归风险。
- 主入口 `MainActivity` 当前按产品要求锁定竖屏（不等于所有 Activity 均锁定），并在 targetSdk 36 使用 Activity 级兼容属性保留大屏限制；Android API 37 将取消该退路，因此这是有期限的产品/适配决策。
- QLZ 使用默认正式环境和用户确认的现有 appKey；用户于 2026-09-21 确认正式环境尚未部署，正式联调暂缓，客户端不回退测试配置。QLZ 1.3.0.5 弱 TLS、腾讯人脸 6.6.2 的 16 KB 对齐与 consumer rules 风险仍按用户确认由标准 Release 告警，不能扩大为其他失败自动放行。
- 大量 route-bound UI 仍在 `:app`，这是维护成本问题，不代表当前用户流程不可用。

开放问题和优先级见[路线图与开放问题](../analysis/project-review.md#17-分阶段技术方案与实施顺序)。
