## Why

评估 H5 需要主动进入原生客户详情，目前 NativeBridge 仅提供关闭方法，无法表达目标客户。同时核对 SDK 评估链路中已结束页面的移除与正常返回，避免固定回首页、退回已结束检测或旧完成状态重复跳转。

## What Changes

- 评估表单及报告支持 `window.NativeBridge.enterUserDetails(pingguuserid)`；参数为客户详情接口使用的客户 ID，用户已确认。
- 接收有效调用后关闭当前 H5，查询并显示指定客户详情；返回时正常出栈到保留的原生来源页，不保留 H5，不固定回销售首页。
- SDK 上传成功后释放会话、移除本轮已结束的设备/检测页，再显示结果页；普通返回只退出当前页，保留其他有效页面。结果页返回不再固定首页，也不回到已结束的测量过程。
- 登记填写页进入确认页时关闭填写页，不再支持返回修改；确认提交失败则留在确认页并保留重试数据，成功后关闭确认页进入提交结果页。取消离开同样不保留已退出页面。
- 完成状态不得在页面重建时重复跳转；打开客户详情不得清空仍保留的结果页客户、recordId 和结果数据。
- 销售客户列表、提醒列表及详情同时改用现有页面栈；统一返回只出栈，严禁非特殊场景以指定目标跳转替代返回。页面展示与业务查询契约不变。
- 保留 `closeWebView()` 的现有行为；进入详情不等同于提交评估，不触发表单关闭完成逻辑。
- 非评估网页及隐私弹窗不提供有效的客户详情跳转；复用现有容器有效性及单次导航保护。
- 非目标：通用桥分发框架、JS 注入、URL 白名单、H5 结果关联协议、新增业务接口、厂商 SDK 二进制/配置及测量上传规则修改、无关页面重构。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `legacy-h5-close`：最小 NativeBridge 从仅关闭扩展为显式方法，限定客户详情操作的容器范围。
- `evaluation-h5-close`：新增评估 H5 进入指定客户详情、移除自身及按保留页面栈返回的契约，并明确评估入口登记页面的关闭行为。
- `device-h5-evaluation-flow`：补充 SDK 完成后的中间页移除、返回和恢复规则，修改“展示真实等级并保留首页”中固定回首页的要求；等级、查询接口及 H5 打开顺序不变。

## Impact

- `:app` 的 NativeBridge、WebViewActions/WebViewScreen、WebView 路由及销售页面状态衔接；复用客户查询与详情 UI，分离详情目标与仍保留的结果页上下文。
- 复用 `GET /V1/Sale/GetUserLatentDetail?id=...`，不修改服务端 API、依赖或权限。
- 补充桥接、导航及离线 H5 调用测试，同步产品、页面地图及 H5 集成说明。
- 新方法仅导航并以当前登录态查询，不向 JS 返回客户信息；服务端继续负责客户数据访问授权。该接口不认证调用 frame 身份，不扩展到协议/隐私容器。
- 线上联调依赖 H5 调用约定方法及有效测试客户；离线验证不依赖 QLZ 设备或生产环境部署。

## Implementation Status

已实施用户最终确认的正常返回栈方案，删除最初固定回首页的未提交实现。三项主规格已同步；代码、离线页面链路、真实 WebView 和混淆接口验证见 tasks。未执行线上 H5/真实 BLE 联调，本次离线验证不代表厂商正式环境就绪。变更尚未归档。
