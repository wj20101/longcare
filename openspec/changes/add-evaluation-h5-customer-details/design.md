## Context

动机见 [proposal](proposal.md)。当前 `NativeBridge` 使用 `@JavascriptInterface` 注册关闭方法，已有主线程调度、容器有效性、单次关闭及释放保护。客户详情在 `HomeRoute` 内由 `SalesNavigationState` 管理，`SalesViewModel.loadCustomerDetail(Int)` 调用现有查询接口。

表单路由 `isEvaluation=true` 表示关闭后进入完成页；报告不设置该标记，关闭只返回来源页。客户详情能力必须同时支持表单和报告，不能把报告改成表单用途，也不能依据隐藏标题栏推断授权。本设计保留短文档以明确这一导航与能力边界。

检查确认：现有销售页面是 `currentPage` 切换及手动返回目标，不是完整页面栈；登记提交后草稿仍留在宿主；设备完成、取消及宿主销毁已调用会话释放。已运行的 23 项测试只覆盖现有会话与导航行为，不证明本轮新契约。

## Goals / Non-Goals

**Goals:** 复用现有桥和页面，区分页面关闭与普通返回；已结束页面不再进入返回路径，其他有效页面及其数据保持可恢复。

**Non-Goals:** 不重写无关业务页面，不新增导航框架、消息协议、返回结果关联、注册表、分发器或服务器 API，不调整厂商 SDK 配置、测量上传规则、H5 内容和 URL 策略。

## Decisions

1. 在 NativeBridge 直接新增显式注解方法，通过可选客户详情回调传递 ID。先验证参数，再复用现有主线程、有效性和单次导航保护；无回调或参数无效不消耗导航机会。接受数字与数字字符串的具体桥接转换以真实离线 WebView 测试验证，不增加拼写别名或包装脚本。
2. WebView 路由增加默认关闭的客户详情能力标记，由表单和报告入口显式开启，随路由保存恢复。它独立于现有 `isEvaluation` 和标题显示标记；普通网页、隐私弹窗不接入业务回调。不以 URL、标题或页面 DOM 推断用途。
3. 受影响的登记、设备、结果及详情链路使用现有 Navigation 3 的可保存页面栈语义；普通前进压栈，返回弹栈，已结束页面移除或替换。移除该链路中硬编码回首页、手工模拟上一页的逻辑，不并行维护第二套路由栈或新增导航框架。复用现有 AppNavigator 的 pop/replace 操作和页面 UI。
   根据用户补充的统一返回约束，销售客户列表、提醒列表及提醒详情也直接使用同一页面栈，删除销售页面枚举切换器模拟返回的逻辑；不修改这些页面的显示与业务查询契约。首页 Tab 切换仍是首页内部 UI 状态，不伪装为页面返回。
4. H5 进入详情时替换当前 H5 entry；若紧邻来源已是同一客户详情，则仅关闭 H5 并刷新来源详情，避免重复页面。其他情况保留原生来源 entry，返回自动回到它。不使用旧方案的待打开客户 ID 加固定 HOME 路由，也不清空来源结果。详情按自身客户 ID 查询，结果页保留自身客户 ID、recordId 和数据，不通过全局 selectedCustomerId 相互覆盖。
5. 填写页到确认页为替换，不保留返回修改；确认页持有提交所需资料和照片，校验或接口失败不导航、不清理，允许重试。成功后替换为结果页，释放已不用的表单及照片；后续评估仍需的客户 ID、地址、pgUrl 等只保留必要业务上下文，不能随表单清理丢失。拍照/预览等临时工具不是登记业务下一步，不因打开工具提前清空未提交数据。
6. 设备扫描、连接和进度属于同一次会话，状态驱动的页面转换不反复堆叠历史；普通取消执行既有释放再退出当前页。上传成功时关闭会话，移除本轮设备/进度 entry 并显示结果页，保留此前有效页面。失败停留检测页重试，不把 100% 当成功。结果页顶部返回、系统返回及退出结果的完成操作均弹出结果页，不固定首页。
7. 将一次性完成导航与可恢复结果数据分开，完成动作消费后不得因重组、返回或进程恢复重新跳转。不要通过清空结果记录来阻止重复导航；保留现有请求取消、SDK 迟到事件和资源释放保护。进入客户详情不调用 `onEvaluationH5Closed()`，不触发提交或额外 GetCheckResult。
8. 保留现有 `@Keep` 和释放策略，不加全局 R8 保留或 Lint 豁免。新方法只触发导航及当前登录态查询，不向 H5 传回任何客户资料，不改变服务端鉴权要求。

## Risks / Trade-offs

- [旧完成状态把详情覆盖回结果页] → 消费一次性导航动作，保留结果数据，覆盖同客户、不同客户、返回和重建回归。
- [页面关闭时提前清理导致提交重试或评估缺数据] → 确认页接管提交数据，失败保留；成功仅传递后续所需上下文，取消才释放未使用数据。
- [已结束页面残留或 SDK 状态互跳堆栈] → 对实际 entry 序列断言，而不只断言当前显示页；覆盖登记确认、成功、失败、检测完成/取消和重复事件。
- [数字参数在实际 WebView 转换不一致] → 离线 HTML 调用数字和字符串两种形式，同时验证非法值无副作用。
- [多次 JS 调用造成重复导航] → 关闭与进入详情共享单次导航状态，覆盖交错调用、后台及销毁后的调用。
- [接口可被评估容器中的 frame 调用] → 不声称来源认证，仅启用导航能力，不回传数据；服务端继续校验访问权限，协议/隐私容器禁用业务回调。
- [只做 JVM 测试不能证明真实桥注册与 R8 可调用] → 补充离线 WebView 仪器测试，构建 Release 并检查保留；可用设备上验证混淆包调用，不依赖厂商检测。

## Migration Plan

无需数据库、依赖或服务端迁移；新路由能力字段默认关闭。本次链路的恢复规则以仍有效的页面 entry 和必要业务参数为准，不恢复已完成表单、检测或关闭的 H5。客户端发布后，H5 使用约定方法；旧客户端没有新增方法，H5 发布时需协调客户端覆盖范围，不由客户端注入兼容代码。回滚本次桥及导航增量即可恢复原行为，回滚需同步停用 H5 新方法调用。

## Implementation Status

已使用现有 Navigation 3 栈落实页面替换与普通出栈，移除销售手写返回目标及旧待跳详情状态。等级展示及上传/查询契约保持不变；主规格已同步，任务验证完成，真实厂商服务联调不在本次离线验收证明范围内。
