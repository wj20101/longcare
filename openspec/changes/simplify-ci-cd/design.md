## Context

动机和范围见 proposal.md。基线为 7a375c09：影响分析结果未用于选择 JVM 测试，Release 在正式构建前推送版本，缓存清理有三个内嵌入口和一个定期入口。全仓引用检查未发现 `.github/scripts/run-baseline-profile.sh` 的调用方；现用 Baseline 工作流直接执行 Gradle Managed Devices。

通过 android-cli 核对 [Android CI 自动化建议](https://developer.android.com/training/testing/continuous-integration/automation)：JVM/Robolectric 适合快速基础验证，设备测试有额外环境成本。本方案保留分层验证，不引入新测试服务。

## Goals / Non-Goals

**Goals:** 直接删除确认无用的实现和维护入口；测试覆盖真实业务；发布步骤与副作用清晰；失败仍明确阻断。

**Non-Goals:** 不开发依赖图分析器、流水线编排框架或复杂的验证证据服务；不删除仍有调用方的 registry、厂商接入工具、健康监测；不改业务功能或历史发布记录。

## Decisions

### 1. 固定完整 JVM 验证，保留小型冒烟选择器

CI 使用单一任务入口执行各业务模块现有 JVM/Debug 单测、App 构建和必要 Lint，App 不使用当前三类 `--tests` 过滤。实施时用 Gradle task graph 与 XML 结果核对 Android 和纯 JVM 模块均被包含，不能把“全量”写成仅 App 全量。

移除 `ALL_MODULES`、`selected_modules`、`affected_scope`、无消费的模块输出和常规 Debug AAB 分支。原检测脚本只留下设备冒烟范围判断并按职责改名，更新所有调用与测试，不做旧名称转发兼容。

代码/构建 PR 和 Push 均执行完整 JVM 验证。手动运行必须选择真实基础冒烟，不因 HEAD 等于远端分支而全部跳过。仅文档改动仍避免昂贵构建，但执行文档一致性检查。平台、启动、导航、WebView、服务和相关测试/CI 执行链路的变更选入对应离线冒烟；纯业务逻辑使用 JVM 测试。默认模板包名测试删除，由实际启动/页面测试替代；有账号、硬件或在线数据前提的测试不放入无人值守集合。差异基线不可用时保守执行基础冒烟。

不采用完整模块影响图，当前维护成本高于收益；不删除全部 instrumentation。

### 2. Release 只承担正式发布职责

删除 Tag 触发和拒绝分支、发布时 Baseline 生成选项/步骤、发布时切换腾讯依赖来源及坐标的选项。保留版本化的本地/Maven 接入能力及专项验证，依赖变化先走正常代码审查与 CI。

继续核对准确源提交的成功 CI，按 SHA 查询而非只检查最近 20 次全库运行。不再生成无消费的 Debug APK。第一阶段保留 Release 中必要的 Lint/厂商政策检查，不为了省时新增复杂 artifact 证明协议；同配置的普通静态门禁已由目标提交 CI 提供，可去重，签名/导出组件/R8/正式产物检查不可去重掉。

版本在本地递增后构建及验证，校验通过才创建并推送版本提交，再按该提交发布。发布使用单一稳定并发组且不自动取消；不强推，分支在构建期间前进时明确失败，不混用新源码与旧产物。应用版本只在 `constants.gradle.kts` 维护，文档仅链接该来源；删除应用版本文档校验及发布同步逻辑，版本提交仅允许修改构建常量。SDK、Gradle 和依赖文档检查，以及正式产物版本一致性检查保持不变。发布失败不自动回滚远端或覆盖历史附件；保留可诊断产物，重跑不覆盖已发布标签。

### 3. 单一存储维护入口

删除 CI、Release 和 Baseline 的 `cleanup-caches` job；定期维护保留。近期保护期内创建或使用的缓存必须跳过，达不到容量目标只报告，不强删热点缓存。正常构建不得因清理 API 失败变红。

统一 Actions 诊断/测试报告最低保留 7 天，不再用 2 天规则或容量条件提前删保护期内产物；超过容量时先删到期项，仍超限则告警。GitHub Release 安装包和 mapping 继续长期留存，不修改历史文件。保留 dry-run 并用 API 替身测试，实施验证不实际清空远端存储。

### 4. 删除重复和僵化约束

直接删除无调用旧 Baseline 脚本。每个 job 的测试报告只上传一份，失败诊断只补充独有日志；去除普通 CI 无实际产物的 Baseline APK 上传。共享环境 action 只保留环境准备，零散门禁开关收敛为明确验证入口，不抽象成可配置框架。

精简 workflow 守卫对步骤名称、固定时长、旧命令形式的断言；保留触发语义、必要权限、测试覆盖、失败阻断、KVM、发布写入时机、产物完整性等行为测试。删除的功能连带清理测试/参数/文档，不保留空壳。其他低频工具只有确认无引用且无独立维护用途才删除；本次不将全仓清理混入 CI/CD。

### 5. 专项入口保留但收窄

Baseline Profile 独立定期/手动生成；腾讯 Maven 切换验证仅在相关接入文件变化或手动触发，不因普通版本号变动重复构建。健康监测保持非发布阻断，不新增监控体系。各模拟器入口统一已有 KVM 权限等待行为，避免重复实现继续漂移。

## Risks / Trade-offs

- 完整 JVM 集合可能暴露既有失败或增加耗时 → 对比测试结果与运行时长，修复实际问题，不以删除真实测试换取绿色。
- 过度收窄冒烟导致漏测 → 用路径场景测试和真实离线 UI 用例验证选择；手动运行与未知基线有保守路径。
- 保护缓存/报告后可能超过预算 → 只告警并调整预算，不把容量策略伪装成保留期限。
- 发布推送与 GitHub Release 不是原子事务 → 构建失败零远端写入，推送/发布失败明确停下，保留产物，不自动重写版本历史。
- 无法用 Debug 测试保证所有 R8 运行路径 → 保留 Release 构建、现有 R8/产物检查，报告真机验证边界，不宣称零崩溃。

## Migration Plan

先补行为测试，再分步修改 CI、存储和 Release，最后删除旧实现并同步引用。每步可由 Git 恢复；不批量删除远端缓存/Release。先完成离线测试及本地构建，再在用户授权推送后验收 Actions；正式发布另行获得授权，不以验证流程为由自动发布。
