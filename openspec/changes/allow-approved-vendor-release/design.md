## Context

基线为 master `57eb5e46`；用户已明确确认保留 QLZ 测试配置，暂不处理厂商问题。最近检查中 production 配置脚本因这四类既知事项退出，vendor readiness 对现有 QLZ TLS finding 退出。此次明确授权覆盖旧文档中“这些事项一律阻断”的策略，但不接受新的运行时崩溃或其他质量失败。

## Goals / Non-Goals

**Goals:** 最小改动现有脚本与 workflow，将已接受事项改为可见警告，完成最终混淆包验证并推送 master。

**Non-Goals:** 不引入发布豁免框架、运行时分支、SDK 替换、业务重构或新的 R8 整包保留规则；不发布应用商店或服务端升级通知。

## Decisions

1. 直接在现有检查中调整已接受事项的报告和退出语义，明确打印 WARN 与原因；输入错误、非法模式仍失败。同步 workflow 步骤名称、质量门禁注册和脚本测试，不使用全局 continue-on-error 或关闭 Lint。风险接受只覆盖本轮确定的包与问题，其余问题仍由既有 allowlist/质量检查阻断。
2. production 构建使用合法 Release 签名，显式关闭 acceptance 和 unsigned/debug fallback，保留 R8 及资源压缩；记录产物和 mapping，不依赖文件名判断是否混淆。
3. 复用已有测试和设备，不新增通用测试框架。完整 JVM/Debug 测试保持原样；API 24/37 运行实际 R8 目标中的 8 项 SDK 消息/Gzip 专项，核对 test APK 无运行库副本并验证失败报告。正式包 UI 用外部设备操作，不为 AndroidJUnitRunner 保留被 R8 删除的无用 API。
4. 真机烟测重点为冷启动/重启、保留登录态与导航恢复、销售列表/详情接口解析、H5 展示/关闭/返回、原生等级读取；护理相关功能使用可用且已授权的测试账号/订单检查，不擅自提交真实护理服务。QLZ 正常真实链路已有本轮证据，可在确认业务代码、AAR、依赖和 R8 规则未变时注明复用；不能声称所有硬件异常已经补测。
5. 发现项目侧 Release 崩溃先定位具体堆栈并最小修复、补回归，不用大范围 keep 掩盖；缺少账号、设备或签名时报告实际阻塞，不虚报通过。

验收发现的恢复缺陷：系统回收进程后，客户 ID 和页面恢复，但客户详情模型只在内存且未触发重查。按任务 2.4 的项目侧缺陷修复范围，仅在进入详情页且没有数据/在途请求/错误时按已保存 ID 重查，失败继续使用原有手动重试，不在所有页面或 H5 返回时自动查结果，不新增恢复框架。

## Risks / Trade-offs

- 风险接受保留弱 TLS 和测试环境行为 → 清晰警告、不打印 key/token，不写成已修复。
- 厂商 native 兼容性和 consumer rules 风险仍在 → 明确为已接受剩余风险，不能承诺所有设备、渠道通过，R8 验收不消除此风险。
- 自动测试覆盖有限 → 最终结果列出设备、变体、路径和未覆盖项；不宣称“代码和业务绝对无问题”。

## Migration Plan

先完成脚本正负回归，再构建正式产物与实际设备验证，最后提交/push、核对最新 CI 并合入 master。同步 AGENT.md、OpenSpec 上下文和发布/QLZ 文档中的旧策略，只更新当前规则，不重写历史验收记录。回退时定向恢复本次发布策略改动，保留其他已合入业务代码。
