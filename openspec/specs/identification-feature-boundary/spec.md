# identification-feature-boundary Specification

## Purpose

建立可被构建守卫与业务回归共同验证的身份识别功能边界，使页面、状态和交互由同一 feature 完整持有，同时保持根导航、平台能力和厂商 SDK 集成的稳定契约及现有用户流程。

## Requirements

### Requirement: 身份识别功能具有单一页面所有权
工程 SHALL 由身份识别 feature 持有主身份识别页面、页面专属资源、屏幕状态装配和用户事件处理；应用壳层 MUST 仅承担根导航组装、跨目的地结果桥接以及需要 Activity 或厂商环境的平台适配。质量验证 MUST 阻止身份识别页面重新出现在 legacy 应用功能目录，也 MUST 阻止身份识别 feature 反向依赖应用壳层实现。

#### Scenario: 页面边界符合约束
- **WHEN** 维护者运行架构与模块边界验证
- **THEN** 身份识别主页面及其专属资源只归属于身份识别 feature
- **AND** 应用壳层仅通过 feature 的公开入口和显式回调完成组装

#### Scenario: 页面回流应用壳层
- **WHEN** 变更在 legacy 应用功能目录新增身份识别页面文件，或从身份识别 feature 引用应用壳层实现
- **THEN** 质量验证 MUST 失败
- **AND** 输出 MUST 指明违规路径与允许的依赖方向

### Requirement: 身份识别路由集成契约保持兼容
迁移后系统 SHALL 保持既有类型安全路由、返回栈行为、共享订单状态所有者和跨目的地返回结果语义；相机照片、人脸照片及默认人脸验证结果 MUST 由身份识别页面至多处理一次，并在处理后清除，避免页面重建或重新进入时重复提交。

#### Scenario: 从服务单进入并返回
- **WHEN** 用户从既有服务单流程进入身份识别页面后使用页面返回按钮或系统返回键
- **THEN** 两种操作均返回同一上级目的地
- **AND** 不创建重复目的地、不丢失当前订单上下文

#### Scenario: 子页面返回结果
- **WHEN** 相机、手动人脸采集或默认人脸验证目的地返回有效结果
- **THEN** 身份识别流程使用原有返回契约处理该结果
- **AND** 结果在确认接收后被清除且不会因生命周期重建再次处理

#### Scenario: 子页面没有有效结果
- **WHEN** 用户取消子页面、返回空结果或结果已被消费
- **THEN** 身份识别页面保持可继续操作
- **AND** 不发起照片上传、验证成功或下一页导航

### Requirement: 页面状态与不可丢失动作遵循单向数据流
身份识别页面 SHALL 以不可变且一致的可观察状态渲染验证、上传和人脸设置状态，用户交互 SHALL 作为事件进入状态持有者；需要导航或提示且不可丢失的动作 MUST 保留到活动页面明确确认消费，并按队列顺序至多执行一次。

#### Scenario: 页面在生命周期切换后恢复
- **WHEN** 页面在验证、上传或等待用户动作期间暂时停止收集并随后恢复
- **THEN** 页面根据最新持久状态恢复正确的进度、成功或错误展示
- **AND** 停止收集期间产生的不可丢失动作仍可被处理

#### Scenario: 已确认动作不会重放
- **WHEN** 页面执行一个导航或提示动作并确认消费后发生重组或重新收集
- **THEN** 系统不得再次执行该动作
- **AND** 队列中的后续动作仍保持原有顺序

#### Scenario: 渲染组件触发用户事件
- **WHEN** 用户选择服务人员验证、老人拍照、重试或返回
- **THEN** 渲染组件只提交对应用户事件或集成回调
- **AND** 不直接操作导航控制器、Activity 或厂商 SDK UI

### Requirement: 平台与厂商人脸验证通过受控边界执行
需要应用上下文或厂商 UI 的人脸验证 SHALL 由应用壳层的平台适配器执行，身份识别 feature SHALL 仅发布带唯一标识的启动请求并接收关联结果。每个请求 MUST 至多启动一次；过期或标识不匹配的结果 MUST 被忽略，取消、失败和成功事件 MUST 保持既有业务状态转换。

#### Scenario: 启动厂商人脸验证
- **WHEN** 身份识别状态产生新的有效厂商人脸启动请求
- **THEN** 应用壳层使用既有厂商适配器启动对应 UI
- **AND** 身份识别 feature 不直接引用厂商 UI 实现或应用壳层命名空间

#### Scenario: 页面重组期间存在同一请求
- **WHEN** 页面在同一启动请求尚未变化时发生多次重组或重新收集
- **THEN** 厂商人脸 UI 只启动一次
- **AND** 请求在确认交付后从待启动状态移除

#### Scenario: 厂商事件返回
- **WHEN** 厂商适配器返回与活动请求匹配的初始化、成功、失败或取消事件
- **THEN** 事件被送回原身份识别流程并产生与迁移前一致的状态转换
- **AND** 其他请求的迟到事件不得改变当前状态

### Requirement: 身份识别主业务行为保持等价
模块迁移 SHALL 保持服务人员验证、老人拍照、权限说明、照片上传、错误提示和成功后服务选择的既有顺序与可达性，不得因源码所有权变化改变网络契约、持久化数据或用户可见结果。

#### Scenario: 老人照片权限获批并上传成功
- **WHEN** 用户确认相机用途、授予权限、完成老人拍照且照片处理与上传成功
- **THEN** 系统保持当前订单上下文并进入既有服务选择目的地
- **AND** 上传成功状态被重置以避免重复导航

#### Scenario: 相机权限被拒绝
- **WHEN** 用户拒绝身份识别页面发起的相机权限请求
- **THEN** 页面显示既有权限不足提示并停留在当前流程
- **AND** 用户之后授予权限时仍可重新发起拍照

#### Scenario: 验证或上传失败
- **WHEN** 服务人员验证、老人照片处理或上传失败或被取消
- **THEN** 页面显示与既有流程等价的错误或取消反馈
- **AND** 用户可重试或返回，不会被误标记为验证成功
