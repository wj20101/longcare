## Purpose

> 2026-09-21 已实施修订：下述设备结果/报告要求取代旧“上传后自动打开 H5”顺序；`device-h5-evaluation-flow` 主规格与代码已同步。纯表单、最小关闭接口和发布风险策略不变；真机验收仍待执行。

该能力让销售人员在 LongCare 应用内完成 QLZ 设备发现、连接、五指检测、结果上传和异常恢复，同时保持现有客户评估与报告契约，并确保蓝牙会话随页面生命周期可靠释放。

## ADDED Requirements

### Requirement: 应用内自定义设备评估流程
系统 SHALL 在 LongCare 销售评估页面内呈现设备自动评估全过程，不再为了扫描、连接、检测或完成结果而打开 QLZ SDK 内置检测页面或报告页面。

#### Scenario: 使用有效 Token 进入设备评估
- **GIVEN** 已选择有效客户且成功取得未过期的检测 Token
- **WHEN** 用户授予当前 Android 版本所需权限并开始设备评估
- **THEN** 系统在 LongCare 自有页面中进入设备扫描状态
- **AND** 不启动 QLZ SDK 内置检测 Activity

#### Scenario: Token 不可用
- **GIVEN** 检测 Token 缺失、过期或被 SDK 拒绝
- **WHEN** 用户尝试开始或恢复设备评估
- **THEN** 系统 SHALL 沿用现有 Token 恢复规则重新获取一次 Token
- **AND** 恢复失败时显示可理解的错误并退出本次检测，而不是暴露 SDK Token、错误对象或内部配置

### Requirement: 蓝牙权限与运行条件
系统 SHALL 在开始扫描前检查当前 Android 版本要求的运行时权限、BLE 能力、蓝牙开关和系统定位服务状态，且 SHALL 只在用户明确发起设备评估后请求权限。

#### Scenario: Android 12 及以上缺少附近设备权限
- **GIVEN** 设备运行 Android 12 或更高版本且缺少扫描或连接权限
- **WHEN** 用户开始设备评估
- **THEN** 系统请求附近设备权限，并成对请求前台精确/粗略位置权限
- **AND** 仅在扫描和连接权限、精确位置授权及定位开关均满足后开始扫描；仅粗略位置授权不足以扫描

#### Scenario: Android 11 及以下缺少位置权限
- **GIVEN** 设备运行 Android 11 或更低版本且缺少扫描所需位置权限
- **WHEN** 用户开始设备评估
- **THEN** 系统请求位置权限
- **AND** 仅在权限授予且运行条件满足后开始扫描

#### Scenario: 用户拒绝权限
- **WHEN** 用户拒绝评估所需权限
- **THEN** 系统 SHALL 停留在 LongCare 页面并说明无法扫描的原因
- **AND** 提供重试或退出操作，不启动扫描或连接

#### Scenario: 蓝牙关闭或设备不支持 BLE
- **WHEN** 开始扫描时蓝牙未开启或设备不支持 BLE
- **THEN** 系统 SHALL 显示对应的阻断状态和恢复指引
- **AND** 不进入无限重试、崩溃或虚假的已连接状态

### Requirement: 有界设备扫描与选择
系统 SHALL 展示 SDK 识别到的候选检测设备，并使每次扫描都有明确的开始、结束和重新扫描行为。

#### Scenario: 发现候选设备
- **WHEN** 扫描期间发现一个或多个符合 SDK 规则的设备
- **THEN** 系统显示去重后的设备名称及可区分标识
- **AND** 用户可选择其中一个设备进行连接

#### Scenario: 用户选择设备
- **WHEN** 用户选择候选设备
- **THEN** 系统立即停止当前扫描并进入该设备的连接状态
- **AND** 不再接受本轮扫描产生的新增设备结果

#### Scenario: 扫描超时无结果
- **WHEN** 有界扫描结束且没有候选设备
- **THEN** 系统显示未发现设备状态
- **AND** 提供重新扫描和退出操作

#### Scenario: 用户主动重新扫描
- **WHEN** 用户在未连接状态选择重新扫描
- **THEN** 系统清除过期的候选列表并开始一个新的有界扫描周期
- **AND** 任一时刻最多存在一个扫描周期

### Requirement: 连接和检测状态可视化
系统 SHALL 在应用自有页面中显示当前设备、连接状态、五个接触点状态、检测进度和设备电量相关提示，并根据 SDK 回调保持状态一致。

#### Scenario: 连接成功并开始检测
- **WHEN** 选定设备连接成功且 SDK 开始检测
- **THEN** 系统显示已连接设备并引导用户按正确姿势握持设备
- **AND** 实时展示五个接触点及已完成数量和总数量

#### Scenario: 接触状态变化
- **WHEN** SDK 上报五个接触点状态或检测进度变化
- **THEN** 系统更新对应的视觉状态和进度
- **AND** 已结束或已退出会话的迟到回调不得改变当前页面

#### Scenario: 设备正在充电或电量不足
- **WHEN** SDK 报告设备充电、低电量或不适合继续检测
- **THEN** 系统显示明确原因并阻止用户误认为检测仍在正常进行
- **AND** 提供与 SDK 当前状态相符的等待、重试或退出操作

#### Scenario: 检测超时或设备掉线
- **WHEN** 检测超时、连接丢失或出现弱信号错误
- **THEN** 系统显示可理解的错误状态
- **AND** 提供重新连接、重新扫描或退出中至少一个有效恢复路径

### Requirement: 检测数据仅上传一次且可恢复
系统 SHALL 在一次检测正常结束后自动提交该次检测数据，并在提交期间防止重复上传；上传失败时 SHALL 提供受控重试。

#### Scenario: 检测结束并上传成功
- **WHEN** SDK 报告本次检测结束
- **THEN** 系统只发起一次检测数据上传并显示上传中状态
- **AND** 上传成功后进入原生评估结果页查询本次结果，不自动打开 H5；采样进度达到 100% 但上传尚未成功时不得提前跳转

#### Scenario: 上传失败后重试
- **WHEN** 检测数据上传失败
- **THEN** 系统保留该次可重试数据并显示失败原因
- **AND** 用户选择重试时仅重传该次数据，不重新开始检测或并发提交

#### Scenario: 上传位置与地址信息
- **WHEN** 系统为检测数据提供位置或地址参数
- **THEN** 参数 SHALL 来自当前客户已有业务数据或当前会话已授权取得的数据
- **AND** 系统 MUST NOT 使用 Demo 中的硬编码坐标、地址、设备名称、MAC、Token 或密钥

### Requirement: 完成状态遵守 LongCare 报告契约
系统 SHALL 在 SDK 检测并上传成功后直接显示原生评估结果页，使用当前客户 ID 和本次 recordId 调用 POST `/V1/Sale/GetCheckResult`。结果页 SHALL 使用响应 `pgResult` 展示等级，并提供“查看评估报告”入口，点击后才打开该响应的 `pgUrl`。系统 MUST NOT 自动打开 H5、使用 SDK URL、凭分数推导等级或等待报告关闭才显示结果。纯表单评估流程 SHALL 保持原行为。

#### Scenario: 上传成功并查询结果
- **WHEN** 当前设备会话上传成功
- **THEN** 释放已完成的设备会话，进入原生评估结果页并调用 GetCheckResult
- **AND** 等级来自本次响应 pgResult，例如返回“A级”时显示“评估成功，评估等级为：A级”，不重复追加“级”

#### Scenario: 用户查看评估报告
- **WHEN** GetCheckResult 返回非空报告地址，用户点击“查看评估报告”
- **THEN** 打开本次响应 pgUrl 的 H5，保持现有沉浸式显示且不新增原生标题栏
- **AND** 未点击按钮时停留在结果页，不自动打开报告

#### Scenario: 关闭评估报告
- **WHEN** 报告调用 window.NativeBridge.closeWebView() 或用户按系统返回
- **THEN** 只关闭当前 H5 并回到原生结果页
- **AND** 不触发评估完成业务回调，不新增网页返回结果、关联 ID 或结果协议

#### Scenario: 结果查询失败或内容尚未就绪
- **WHEN** GetCheckResult 失败、pgResult 为空或 pgUrl 为空
- **THEN** 保留结果页，显示相应失败或待同步提示并允许手动刷新同一接口；没有报告地址时不允许打开空网页
- **AND** 不伪造等级、不读缓存旧结果、不切换客户详情或 SDK URL 兜底、不重新检测或上传

#### Scenario: 重复完成事件和状态恢复
- **WHEN** SDK 重复报告上传成功、页面重组或前后台恢复
- **THEN** 不重复压入结果页，不自动打开报告，不启动新的测量或上传

#### Scenario: 切换客户或返回首页
- **WHEN** 用户离开结果页返回首页，或切换到其他客户
- **THEN** 不返回已完成的测量过程，不自动打开 H5；旧客户的迟到结果不得覆盖当前客户结果

### Requirement: 错误与支付状态不得被静默忽略
系统 SHALL 将 SDK 返回的鉴权、连接、设备、测量、上传和需要支付状态映射为应用可理解的状态，且不得把原始敏感信息直接展示给用户。

#### Scenario: 可恢复错误
- **WHEN** SDK 返回可恢复的扫描、连接、测量或上传错误
- **THEN** 系统显示面向用户的说明及与当前阶段匹配的重试操作
- **AND** 重试不会创建第二个并行评估会话

#### Scenario: 不可恢复错误
- **WHEN** SDK 返回无法在当前会话恢复的鉴权、设备或服务错误
- **THEN** 系统停止当前操作并提供安全退出路径
- **AND** 不显示 SDK 密钥、Token、内部 URL、堆栈或开发错误文本

#### Scenario: SDK 要求支付
- **WHEN** SDK 报告本次检测需要支付
- **THEN** 系统显示阻断提示并停止继续检测
- **AND** 在未定义 LongCare 支付契约前仅允许用户退出，不自动打开厂商支付 URL

### Requirement: 会话生命周期与并发安全
系统 SHALL 将 QLZ 扫描和检测资源绑定到当前评估页面生命周期，并确保应用内同一时刻最多存在一个活动评估会话。

#### Scenario: 用户在扫描或检测中退出
- **WHEN** 用户返回、关闭评估或页面被移除
- **THEN** 系统停止活动扫描并释放设备连接与 SDK 回调资源
- **AND** 后续迟到回调不得导航、弹窗、上传或覆盖新的页面状态

#### Scenario: 页面进入后台后恢复
- **WHEN** 活动评估页面进入后台并随后恢复
- **THEN** 系统不得在后台启动新的扫描或新的检测会话
- **AND** 恢复时根据现有会话是否仍安全有效展示继续、重试或退出状态

#### Scenario: 重复开始评估
- **WHEN** 用户连续点击开始、重试或设备项
- **THEN** 系统 SHALL 合并或拒绝重复动作
- **AND** 不创建并行扫描、连接、检测或上传操作
