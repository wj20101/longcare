## 已知限制

### 数据库与缓存

[DatabaseModule](../../core/data/src/main/kotlin/com/ytone/longcare/di/DatabaseModule.kt) 仍仅允许从历史 v1/v2 重建。当前为 schema v4，显式 3→4 迁移只为订单本地状态增加 `local_start_elapsed_realtime`、`local_start_boot_count` 两个可空列，保留本地进度、项目和未上传照片；旧记录保持 null，不推算或补造单调起点。其他缺少迁移路径的版本拒绝打开并保留原数据，后续升级继续需要保数据迁移及测试。

订单内存缓存已绑定会话失效，旧请求不能在换号后回填；照片上传结果先落盘再报告成功。COS 上传与本地数据库不能组成同一事务，上传后进程终止仍可能使重试再次上传；重复业务提交的服务端幂等性仍需结合接口契约判断。

### 计时与提醒

正式开始成功时一次捕获并持久保存墙钟、`elapsedRealtime` 与开机计数，保留首次起点及终态保护。同次开机的有效单调起点用于显示和到期判断，进程重建、CPU 深睡和墙钟校准不再重新延长这段服务时长；跨开机、旧记录缺少单调起点或开机身份未知时明确回退原持久墙钟。这个保守回退仍受墙钟偏移影响，不能把前次开机的 elapsed 值继续使用。持久终态会停止倒计时准备。

原墙钟截止继续作为稳定提醒身份，RTC 时间按当前单调剩余时长换算；系统 `TIME_SET` 重排同一提醒，提前交付的旧 RTC 在单调截止前被拒绝。最后已消费的账号/订单/计划/原截止身份独立持久保存，关闭提醒后仍可阻止相同身份在重启或回拨后重新响铃；只保留最后一条消费记录，不建立完整历史表。跨开机、旧记录或未知开机身份的过期墙钟提醒不补响。校时、首次会话解析后的恢复和提前交付后的重排允许同次开机、有有效单调截止且未消费的已到期记录登记立即系统交付；这覆盖冷启动等待会话超过广播预算，以及检查提前交付后第二次取时恰好跨过截止的情况，仍不从恢复入口直接播放。

提醒诊断将广播入口、验证排队与执行、Receiver 结束、服务入口与取锁、播放器工作线程准备/启动及主线程回调分段关联；应用广播入口延迟包含冷启动和主线程排队，应用 `isHeld` 也不证明系统实际保锁，播放启动返回不证明真实听到声音。代码与回归覆盖不能替代真实断电重启、可听声响或连续每 60 秒上报验收。精确授权不足时仍只做 inexact 降级，有声通知兜底不能绕过系统/用户静音、勿扰或通知关闭。闹铃播放器的文件读取、异步准备和生命周期操作移至同一专用 Looper，服务侧设置准备与总生命周期预算，取消后不再接受旧播放请求。平台底层读取、启动或释放若自身阻塞，应用不能安全跨线程强制中断；主线程不等待，已进入底层的操作与物理声音停止不能承诺硬实时上限。释放抛出异常时，该进程内停止创建新播放器；只有能够排除旧播放仍在执行时才允许有声通知兜底。这是限制资源泄漏与重复响铃的保守策略，不能承诺不重启进程即可恢复底层播放。工作线程与待处理请求须保持有界，具体契约见[倒计时提醒诊断](../architecture/system-overview.md#闹钟计时与延迟诊断)。异步化不保证铃声加载更快，也不是荣耀现场问题根因已确认的证据。

### 厂商依赖

签到、签退、正式开始与持续上报使用 SDK 估计精度不超过 200 米的业务规则；100 米为优先目标，100～200 米可直接使用。这是项目策略，不是高德的真实误差保证；精度合格仍可能发生数据库误差等漂移。高德没有按米数限制回调的配置，质量筛选与有限补采由客户端执行。其他用户偶发现象缺少当时的 SDK 元数据，不能把本地模拟晚到回调或测试通过当作现场根因已证实。

服务端当前没有低精度异常签到/签退协议。客户端在 30 秒动作窗口内等待新回调并保留业务资料供重试，不能既拒绝所有不合格点又保证每次都能正常提交；不使用历史点、空坐标或伪造坐标兜底。后续若提供异常处理接口，须按服务端契约单独接入。定位方案和资源约束见[单次业务定位](../architecture/system-overview.md#单次业务定位)。

Vivo 小于 69 版本的 Home/锁屏停报反馈缺少确切版本、现场日志和 SDK 元数据，不能断言全部来自同一缺陷。当前修复覆盖可见时准备前台服务、实际启动确认、系统重建与前台恢复；厂商自启动、省电限制、强制停止及深度 Doze 仍可使采集或网络中断。现有小米、华为真机与隔离测试不替代现场 Vivo 验收，测试上报出口不代表护理接口线上已验收。

华为 STK-L21（Android 9 / EMUI 9.1）曾在自动管理开启时冻结同 UID 线程，前台通知仍存在；手动允许后台活动后该冻结未再观察到。小米 MI CC9e 也曾在进程存活时长时间 CPU 休眠。现有定位前台服务在有效采集期间持有 CPU 唤醒锁，准备、暂停、授权失效及结束时释放；这解决执行暂停的已确认路径，不能单独保证 SDK 交付新点。系统电池豁免、厂商后台设置与应用持锁是不同条件，不能凭其中一个判断采集正常。历史对照见[定位验证记录](../../validation/location-sdk-foreground-20261022/README.md)。

高德 11.3.101 的独立 USB/JDWP 取证在两机均捕获新网络输入经过 `LocFilter` 分支 2 返回旧 tick、随后 observer 拒发的链路，前台和后台均可出现；另一次无调试器的五分钟拔线窗口，两机公开日志各记录 9 次旧点替换，原始回调均为 0，CPU 和订单检查仍推进。关闭缓存不等于关闭内部过滤。旧版 11.2.100 曾以重复源 tick 产生表面上连续的回调，因此没有回退 SDK 或用旧点补传。导航场景的公开间接旁路不适用于当前护理静止场景，生产没有使用私有字段或冒用导航状态。

当前生产采集改为同一原生客户端上的周期单次请求，首回调或截止后正常停止并保留静默间隔，销售/拍照和订单共享采集，各自保留取消、截止及账号范围。停止不重置源 tick 水位、质量规则或业务去重；不按回调空档自动重建客户端。SDK `APSService` 继续作为绑定组件，前台通知仍由应用 Service 持有。实现契约见[单次业务定位](../architecture/system-overview.md#单次业务定位)。

review 修复前候选 APK 在稳定网络的固定五分钟拔线复测中，两机各得到 10 个新源 tick 和 10 次本地成功，每分钟均 2 次；但华为随后直到停止前又有 135.447 秒无新回调，订单检查继续。因此固定窗口通过，持续运行问题仍未闭合。此前网络变化窗口的小米 6/6、华为 5/5 仍保留为失败，不能被后一次通过覆盖。当前证据缺少原生逐轮 start/stop 边界，尚不能把华为尾部异常归为调度器、SDK 或网络中的某一层；后续需要针对该边界取证，不据此新增推测性恢复。构建、测试范围和两轮结果见[本轮验证记录](../../validation/location-shared-sampling-20261024/README.md)。

公开 stop 没有底层停止确认，SDK 某些旧 HTTP 错误可能向当前全局 observer 广播，应用监听代次不足以识别这种内部跨轮转发。错误子码 0403 和零网络耗时不能细分网络根因，也没有证据证明正常 stop 直接制造该错误。已测通过的本地接收不等于护理服务器成功或地理真值，不能外推所有厂商与整单时长。

三星熄屏停报、首次签退失败，以及荣耀长订单迟响的反馈缺少现场版本、权限和完整事件时间链。代码层另修复了休眠后动作预算失效、前台服务静默拒绝被当成功、旧会话迟到响应误登出新账号等独立缺陷；这些触发条件不能在缺少现场链路时直接归为相应品牌的实际根因。单调时间与计时起点修复也不能证明现场问题全部闭合。需要分别检查新鲜合格回调、客户端拒绝、网络响应与闹钟各阶段时间；没有回调或网络时，不能补传旧点冒充当前正确位置。

1.0.7 线上曾出现 SDK 成功的 GPS 回调被客户端 `TIME` 拦截（一次摘要为 13 次回调、12 次拒绝）。当前已统一源单调时间校验、会话水位与恢复边界，GPS UTC 偏移和校时回归通过；旧日志未保存接收时带符号差值，不能量化该次现场时钟偏差，也不能认定所有停报均由此引起。源 tick 缺失仍保守检查墙钟，后续用 `time` 证据区分具体分支。

华为测试机当前基线是关闭自动管理，手动允许自启动、关联启动、后台活动，并开启本应用系统电池豁免；[官方说明](https://consumer.huawei.com/cn/support/content/zh-cn15850065/)中的“不允许”指不允许优化本应用。应用 `isHeld=true` 不证明厂商仍实际执行该锁，公开系统状态也不证明厂商权限已配置。不修改全局省电或禁用厂商组件；高德 HighAccuracy 不会替用户开启 GPS，提供器设置与每轮观测分开核对。

### 腾讯人脸凭据

现有系统配置接口仍向客户端返回腾讯 AppSecret，客户端直接向腾讯换取 Access Token。当前缓解措施移除了普通配置持久化、内存缓存和 UI 状态中的 AppSecret，并限制了临时凭据与 SDK 回调的会话生命周期；这不能防止受控客户端在响应解析或换取 token 时提取密钥，也不保证 JVM 字符串安全擦除。

该高风险边界尚未闭合。完整修复需要服务端保管 AppSecret、代为请求腾讯凭据，并向客户端提供受限认证参数；本次保持后端 API 不变。厂商线上认证及真实账号切换仍需对应环境验收，离线单测不等同于腾讯服务端与真机验证。

### 性能采集

[BaselineProfileGenerator](../../baselineprofile/src/main/java/com/ytone/longcare/baselineprofile/BaselineProfileGenerator.kt) 当前等待包级根节点，随后执行滑动和返回，并将整个采集块包含到 Startup Profile；没有断言具体业务页面就绪，也不覆盖登录后的完整业务旅程。

因此，生成成功不能证明业务性能收益。只有实际开展性能优化时，再按目标页面调整采集、区分启动和交互路径，并用真机测量收益；这不是普通业务发布的新前置任务。

### 模块与平台

多数 route UI 和销售组装仍在 `:app`，`SalesViewModel` 职责较集中。后续修改相关功能时按需拆分，保持行为和导航栈测试，不为收尾强制进行全量模块迁移。

当前大屏方向约束和定位生命周期规则见[系统概览](../architecture/system-overview.md)，SDK/工具链以[技术栈](../architecture/tech-stack.md)为准。升级目标平台或修改相机、权限、前台服务时，再执行相应场景验证，不重复维护版本快照和通用验收矩阵。
