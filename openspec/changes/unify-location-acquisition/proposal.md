## Why

护理员在客户家静止期间出现公里级位置偏移，现有实现将成功回调近似等同于业务可用位置，且单次、持续、登记和照片水印的缓存与权限行为不一致。需要统一获取与使用规则、删除重复及过期路径，并通过本地测试验证 SDK 采集和客户端传递，不仅靠过滤掩盖问题。本次不进行服务端数据对照，也不扩展线上诊断。

## What Changes

- 单次定位统一为一个入口，覆盖 NFC 核验、位置绑定、开始/结束服务、客户登记和照片水印；持续定位保留独立生命周期，共用 SDK 基础配置和质量校验。
- 删除 quick/fresh 双实现、NFC 入页预定位、业务 5 分钟缓存优先路径和无调用方缓存读取接口，不保留兼容代理或双轨开关。
- 在业务使用前检查样本有效性、新鲜度、精度、来源、可信度及坐标系；客户端不计算距客户距离，不做基于位移或速度的跳点拦截、候选确认、锁点或纠偏。签到和结单的距离判断全部交给服务端。
- 定位结果分类表达失败原因。关键护理操作无法取得可用位置时留在当前步骤，不提交空坐标；登记与照片保持既有位置可选性，不静默复用失效位置。
- 保留订单驱动的持续定位、唯一上报入口、无历史补传及显式恢复契约，覆盖取消、迟到回调、权限恢复与账号隔离。
- 使用 Release 包进行多次独立定位、权限恢复和生命周期验收，检查定位获取是否正常；保留既有诊断，不增加线上质量上报，不将服务端核验作为完成条件。
- 同步清理本次替换导致失效的成员、常量、资源、注释、测试和当前文档，不扩展为全仓清理。

## Capabilities

### New Capabilities

- `unified-location-acquisition`: 统一定位、质量判定、业务消费、异常恢复和可追踪性；仅定义本次真实增量。

### Modified Capabilities

无。现有 OpenSpec 主规格未覆盖本次定位能力；护理会话生命周期仍以系统概览的既有契约为约束，不改倒计时导航或 QLZ 扫描权限规则。

## Impact

- 受影响模块：`:feature:location`、`:core:domain`、`:core:model`、`:core:ui`，以及 `:app` 中 NFC/销售调用方、`:feature:photoupload` 和对应测试。
- 网络范围：核对 `CheckOrder`、`BindLocation`、`StarOrder`、`EndOrder`、`AddPostion` 和登记请求的坐标来源；不新增接口、修改 JSON key 或擅自扩大服务端结单半径。
- 不新增依赖、后台定位权限、持久队列、进程重启任务、轨迹平滑框架、坐标猜测修正或数据库迁移；不将 SDK 升级作为未经验证的修复。
- 兼容性：内部 Kotlin 定位接口一次迁移全部调用方；外部 API 与已有数据保持兼容。关键护理操作不再携带空位置继续，是有意的用户行为变化。
- 验收边界：定位质量规则依据 SDK 元数据语义和本地定位测试制定，不从签到/结单半径推导；仅核对本机 SDK 结果到请求参数的传递，不依赖原始服务单或服务端落库数据。按用户 2026-09-29 收尾决定，取消长时漂移/功耗专项与预设整套验收指标，改为多次独立定位，结合必要自动化、构建和真机权限/生命周期测试交付；不重复人工验证已有覆盖，不放宽现有 CI/签名/R8 门禁。
- 风险：室内信号、Wi-Fi 扫描限制及厂商定位库仍可能返回偏移坐标；严格校验可能降低可用率。多次定位验证本次获取流程，不构成所有环境准确性的承诺。现场原始坐标仅在授权联调中受控获取，默认诊断不得记录精确位置或身份凭据。
