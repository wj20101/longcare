## ADDED Requirements

### Requirement: 模块构建能力与直接依赖保持最小且自洽
每个参与应用交付的模块 SHALL 只启用其生产源码、资源、清单或代码生成实际需要的构建能力，并 MUST 在生产配置中显式声明自身直接使用的依赖；模块不得依靠其他模块的传递依赖获得编译 API，也不得长期保留没有可验证使用方的 UI、平台集成或运行时制品。测试配置中的依赖 SHALL 由对应测试源码或测试运行器证明用途。

#### Scenario: 模块声明与实际用途一致
- **WHEN** 维护者运行模块构建配置验证
- **THEN** 每项生产构建能力和生产直接依赖都能映射到该模块的生产使用方或必要生成步骤
- **AND** 模块能够在不依赖未声明传递 API 的前提下独立编译并完成 focused tests

#### Scenario: 无对应源码的构建能力进入模块
- **WHEN** 模块启用了没有生产源码、资源、清单或生成任务使用证据的构建能力
- **THEN** 构建治理验证 MUST 失败
- **AND** 失败信息列出模块、冗余能力及其验证依据

#### Scenario: 删除依赖暴露真实用途
- **WHEN** 候选依赖移除后编译、测试、lint 或运行验证发现真实直接用途
- **THEN** 该依赖 MUST 恢复为精确的模块直接依赖
- **AND** 不得通过依赖其他模块的传递导出或增加更宽泛依赖规避失败

### Requirement: 冗余删除必须具有可复核证据
工程 SHALL 仅删除同时具备静态引用、构建可达性和受影响行为验证证据的代码、资源、清单或质量入口；单一搜索结果、文件命名、代码覆盖率或收缩器删除报告 MUST NOT 单独作为删除依据，反射、依赖注入、序列化、清单注册、资源标识及脚本人工入口均 MUST 纳入可达性判断。

#### Scenario: 候选项满足删除门槛
- **WHEN** 候选项没有生产引用或动态入口、构建/收缩证据确认其不参与交付，并且删除后的受影响构建与行为验证通过
- **THEN** 候选项可以从工程及其文档、测试和 allowlist 中一并移除
- **AND** 验证记录能够说明删除依据和覆盖的回归边界

#### Scenario: 候选项存在不确定运行时入口
- **WHEN** 候选项可能由反射、清单、依赖注入、序列化、资源、厂商 SDK、远端内容或人工脚本入口使用且无法证明安全删除
- **THEN** 候选项 MUST 保留或移至后续独立验证变更
- **AND** 当前清理不得通过修改外部制品或放宽质量门禁消除该不确定性

### Requirement: 已退役冗余不得静默回流
构建与架构治理 SHALL 对本次确认退役的占位声明、空壳注册、不可达导航入口、重复测试和无所有权质量入口建立可维护的防回归检查；新增空壳只有在具有明确使用方、负责人和可检查退出条件时才允许进入工程。

#### Scenario: 已退役指纹重新出现
- **WHEN** 变更重新引入已确认删除的冗余类型或等价空壳
- **THEN** 质量验证 MUST 失败
- **AND** 输出具体文件、冗余分类和允许的修复方式

#### Scenario: 新增临时空壳具有明确用途
- **WHEN** 构建迁移确实需要短期占位或兼容入口
- **THEN** 维护者 MUST 同时登记使用方、负责人、验证范围和可检查的退出条件
- **AND** 未满足这些字段的临时空壳不得通过治理验证
