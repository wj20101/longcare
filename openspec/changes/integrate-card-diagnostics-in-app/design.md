## Context

变更开始前 `:assistant` 是独立应用，包含五项验证、独立登录和双包发布配置。当前工作区已将两项读卡检测迁入主应用，支持显式选择 NFC/R65C，并删除独立助手。用户所述 RC565 按项目现有 R65C 功能处理，不新增设备协议。

主应用已使用 Navigation 3；登录表单已使用保存状态保留返回后的输入。主应用已有 NFC 业务事件处理，复用底层解析不等于可以复用签到处理链。两项本地检测和单包发布主规格已同步，但入口仍是摇动方案。真机暴露连续摇动无法累计的问题后，用户明确改为长按中央大 Logo，并放弃震动；本次修订替换入口方案，不继续调参。

## Goals / Non-Goals

**Goals**

- 将 NFC/R65C 两项只读检测放入主应用，登录页长按中央大 Logo 后先确认再进入。
- 普通点击不触发，长按无震动；防止持续按住、重复长按和页面切换造成重复弹窗或意外跳转。
- 删除助手应用和仅为其服务的代码、资源、依赖、脚本及说明，未来只维护主应用安装产物。

**Non-Goals**

- 不新增通用插件或测试框架、手势配置后台、跨 APK 跳转、其他入口或旧助手数据迁移。
- 不修改正式业务人脸、相机、签到、H5、认证和升级协议，不处理已接受的厂商问题。
- 不自动卸载旧助手或删除历史 Release，不在本次计划阶段提交、推送或触发发布。

## Decisions

### 1. 小型 Feature 承载读卡，主应用负责入口和平台接入

新增轻量 `:feature:carddiagnostics`，迁移仍需的读卡 UI、HID 输入与状态，复用现有 Core 解析能力，不扩大冻结的 legacy Feature。主应用使用现有 Navigation 3 增加一个检测页面，压入登录页之上，返回只弹出检测页。平台对象不进入 ViewModel，不新增导出 Activity 或外部入口。

NFC 和 R65C 使用显式模式切换，当前模式独占读取。NFC 不可用时展示状态并允许选择 R65C；从系统设置回前台刷新状态。HID 输入捕获只在 R65C 页前台生效，清理延迟提交、焦点和监听后再返回登录。核对主应用 NFC 事件的订阅方，检测期间只走本地显示，不进入业务签到处理。

### 2. 入口改用大 Logo 的标准长按交互

在现有 `LoginBrandingHeader` 的中央大 Logo 上接入 Compose 标准长按，保留原有布局与图片；左上角小 Logo、背景和表单不增加入口。遵循系统长按时长，普通点击不执行动作，手势取消不弹窗。不新增自定义计时器、手势框架或权限。

显式关闭长按自身的触觉反馈，不调用震动接口；点击和长按均关闭 indication，不显示波纹、按压高亮或缩放。标准长按依据 Android CLI 核对的 [Compose 点击与按压文档](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/tap-and-press)，使用当前 Compose 的 `combinedClickable`，设置 `indication = null` 和 `hapticFeedbackEnabled = false`，不自定义反馈框架。

删除 `DeliberateShakeDetector`、入口传感器监听、采样阈值、冷却状态和仅服务摇动的测试；将仍有价值的弹窗/生命周期测试改为长按触发。同步调整 CI 专项测试选择器、架构守卫引用和当前文档，不保留摇动备用入口。长按不依赖加速度传感器，无需缺少传感器分支。

### 3. 长按只打开确认弹窗，导航只能由用户确认触发

使用 Jetpack Compose Material 3 标准 AlertDialog，沿用主题默认形状、间距、排版和 TextButton，不自绘弹窗样式。标题“打开助手”，正文“可进行 NFC 和 R65C 读卡检测，检测数据仅在本机显示。”，按钮“取消”与“打开”。一次持续长按只显示一个弹窗，弹窗显示期间不重复触发。确认时再次检查当前仍是可交互登录页，防止登录成功等异步动作已经改变页面。取消、返回和外部关闭一律不导航；再次进入需要一次新的长按，不设置摇动冷却计时。

只在全局隐私同意且登录页前台可交互时启用入口；登录提交中、其他弹窗显示时不启用。进入后台、离开登录页时清空待确认状态，恢复不会自动弹窗或进入。检测路由按既有 Navigation 3 方式保存页面栈，但未确认弹窗不持久化；保留登录表单现有保存状态，不重构登录流程。

### 4. 本地检测不是业务接口，也不把隐藏入口当作鉴权

任何同意隐私且处于登录页的用户都可能进入，因此只展示本机读卡结果，提供清空与用户主动复制；不保存历史、不上传、不建立助手登录、不修改主应用会话。仅在页面有效生命周期内读取。移除独立助手的相机、人脸、定位等测试代码，但根据引用保留主应用真实业务需要的共享模块、权限和资源。

### 5. 单应用构建与发布同步收敛

读卡迁移验证后删除 `:assistant` 模块及注册、专属资源/依赖、双包命令、CI 的助手构建与上传、助手签名/映射/身份校验和对应废弃测试。必要的业务隔离检查迁移为“诊断不触发签到、无外部检测组件、登录表单不受输入污染”，不通过全局放宽门禁来允许新入口。仅中央大 Logo 新增长按行为。

Release 保留主 APK/AAB、校验和、主应用 mapping、签名、R8、资源压缩、目标提交 CI、Lint、版本递增和 Latest 语义。不新增发布模式。更新文档和主规格的 Purpose/Acceptance Scope，移除与本变更冲突的旧五项验证及 R65C 不验收声明；退役 `dual-apk-packaging`。历史文档作为历史不应被全局字符串替换。

## Risks / Trade-offs

- 长按热区或默认反馈接入错误 → 将热区限定在中央大 Logo，显式关闭触觉反馈，测试短按、长按、移动取消、持续按住及弹窗确认。
- NFC 事件与正式业务共享底层 → 只在活动检测页订阅，明确模式独占，回归正式读卡与签到；禁止直接复用业务提交 ViewModel。
- 隐藏入口发现成本较高 → 接受本次仅中央大 Logo 长按入口，不新增其他隐藏手势或登录后入口。
- 删除助手可能误删共享依赖 → 先查引用再删除，构建主应用 Debug/Release 并运行已有业务回归。
- R8 可能影响迁移后的反射或序列化路径 → 使用真实 Release 包验证启动、入口、两项读取与返回，不新增宽泛 keep 规则。

## Migration Plan

1. 迁移仅读卡能力和路由，补齐模式选择、资源释放及本地隔离测试。
2. 将摇动入口替换为大 Logo 长按及确认弹窗，删除废弃传感器代码和测试，验证无震动、输入保留、生命周期和取消行为。
3. 删除助手及双包构建发布配置，更新必要门禁、文档与主规格。
4. 执行单元测试、UI/生命周期回归、Lint、架构与发布脚本检查，构建主应用 Release APK/AAB。
5. 真机验收中央大 Logo 长按、短按无动作、无震动、取消、重复长按、后台恢复、返回及 NFC/R65C；验证摇动不再触发。硬件未就绪时列出未验收项，不以模拟结果替代。
6. 实施完成后报告变更和验证证据；提交、推送及线上发布另按用户授权执行。若未发布前需回退，用版本控制撤销本变更自身内容，不动其他并行修改；已发布后通过新版本修复，不删除历史附件。
