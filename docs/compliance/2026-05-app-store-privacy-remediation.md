# 应用市场隐私合规整改说明

- 原始整改日期：2026-05-31
- 客户端现状复核：2026-08-27

> 本文是 2026-05 应用市场整改记录和待办清单，不是“当前线上隐私政策已经发布并通过所有市场审核”的证明。提审前必须由产品/法务按当前 APK、第三方 SDK 清单和线上政策重新复核。

## 背景

本说明用于响应 OPPO、vivo、腾讯应用宝在 2026-05-26 至 2026-05-27 的审核反馈。整改目标是确保首次启动/登录同意流程、应用内隐私政策入口、隐私政策披露内容和提审说明保持一致。

## 已完成的客户端整改

1. 首次启动隐私弹窗保留“同意并继续”和“不同意”两个明确按钮，用户不同意时退出应用。
2. 登录页协议勾选默认未选中，登录和发送验证码前必须由用户主动勾选。
3. 登录页文案由“登录即表明已阅读并同意”调整为“我已阅读并同意”，避免被判定为隐式同意。
4. 未勾选协议时点击发送验证码或登录，仅提示用户主动勾选，不再由弹窗替用户勾选并继续提交。
5. “我的”页新增“用户协议”和“隐私政策”常驻入口。审核访问路径：进入应用 -> 我的 -> 隐私政策。

## 需同步更新线上隐私政策的内容

当前线上隐私政策已披露 Android ID、IMEI、位置、摄像头/相册等内容，但仍需补充应用宝和 vivo 明确指出的项目。建议将以下内容更新到 `https://www.ytone.com.cn/longcare/xieyi/yinsi.html`。

### 系统权限与能力说明

| 信息/能力 | 使用场景 | 收集/使用方式 | 是否用户同意后触发 |
| --- | --- | --- | --- |
| Android ID、应用安装实例 ID | 账号安全、异常登录识别、防刷、防攻击、服务请求风控 | 通过 Android 系统 API 读取 Android ID；若不可用则生成应用安装实例 UUID | 是 |
| 设备 MAC 地址、软件安装列表 | 第三方 SDK 安全风控、定位与稳定性能力可能涉及 | 客户端不主动读取；如第三方 SDK 检测涉及，应按 SDK 名称、处理目的和信息范围在隐私政策中披露 | 是 |
| 设备信息 | 兼容性适配、问题排查、账号安全 | 读取设备型号、系统版本、应用版本、网络类型、网络运营商 | 是 |
| 位置信息 | 护理服务签到、服务过程位置核验 | 在用户授权定位权限后获取经纬度 | 是 |
| 摄像头/业务图片 | 护理服务照片、人脸核验、销售客户登记、服务记录留痕 | 在用户授权相机权限后拍摄并在应用私有/专属目录处理图片；当前标准业务流程不提供相册选择，Manifest 未声明相册读取权限 | 是 |
| 剪贴板/剪切板写入 | NFC/设备测试页面中复制卡号或标签 ID，便于人工排查 | 仅在用户点击“复制”或测试流程触发时写入剪贴板，不主动读取剪贴板内容 | 是 |
| 开机广播/自启动能力 | 设备重启后恢复用户已设置的未完成服务提醒 | 接收 BOOT_COMPLETED 后，仅在用户已同意隐私政策、已登录且存在待恢复服务提醒时执行提醒恢复 | 是 |
| 安装未知来源应用权限 | App 内版本更新后跳转系统安装界面 | 仅在用户主动点击更新安装时申请/跳转系统授权，不扫描软件安装列表 | 是 |

### 第三方 SDK/服务清单

| SDK/服务 | 用途 | 可能处理的信息 | 第三方主体 |
| --- | --- | --- | --- |
| 高德定位 SDK | 定位与服务位置核验 | 设备信息、网络信息、位置信息，具体以高德 SDK 实际处理为准 | 高德软件有限公司 |
| 腾讯 Bugly | 崩溃分析和稳定性排查 | 设备信息、系统版本、应用版本、崩溃日志 | 深圳市腾讯计算机系统有限公司 |
| 腾讯云人脸核验/人脸识别服务 | 护工身份核验、防止冒用 | 人脸图像/视频、身份核验过程数据、设备基础信息 | 腾讯云计算（北京）有限责任公司或其关联主体 |
| 腾讯云 COS | 护理服务照片和业务文件存储 | 用户主动上传的图片/文件及必要上传日志 | 腾讯云计算（北京）有限责任公司或其关联主体 |
| Google ML Kit 人脸检测 | 默认服务人员核验中的单人、姿态、眼睛状态和眨眼检测 | 在设备侧分析相机帧；实际 SDK 遥测与数据处理范围需按提审时厂商最新披露复核 | Google LLC |
| 俏郎中（QLZ）评估 SDK | 销售客户的蓝牙设备自动评估 | 蓝牙权限、检测设备标识、服务端一次性 Token、评估进度/结果事件；具体信息范围以供应商合同和最新隐私清单为准 | SDK 提供方法定主体需由产品/法务确认 |
| Android 系统剪贴板能力 | 用户主动复制 NFC 卡号/标签 ID | 写入用户选择复制的文本内容 | Android 系统能力，不向第三方共享 |

如第三方 SDK 实际检测报告显示“软件安装列表”“设备 MAC 地址”等项目，应在该清单中追加对应 SDK 名称、处理目的、处理方式、信息范围；若客户端不主动收集，应在说明中写明“本 App 不主动读取软件安装列表，不主动读取设备 MAC 地址；如第三方 SDK 因安全风控/定位能力涉及相关信息，以 SDK 清单披露为准”。

### 建议替换/补充文案

可在“我们如何收集和使用你的个人信息”中补充：

> 为保障账号安全、识别异常登录、防止恶意注册和攻击，我们会在您同意隐私政策后，通过 Android 系统 API 获取 Android ID；如 Android ID 不可用，我们会生成应用安装实例 ID。上述信息仅用于本 App 的账号安全、请求风控和服务稳定性保障。

可在“系统权限及调用说明”中补充：

> 剪贴板/剪切板：本 App 不会主动读取您的剪贴板内容。仅在 NFC 或设备测试相关页面中，当您主动点击复制卡号、标签 ID 或测试结果时，将您选择的文本写入系统剪贴板。

可在“自启动及后台运行说明”中补充：

> 开机广播/自启动能力：本 App 声明接收设备重启广播，仅用于在用户已同意隐私政策、已登录且存在未完成服务提醒时，恢复服务结束提醒。若不存在待恢复提醒，或用户未同意隐私政策、未登录，本 App 不会执行提醒恢复。

可在“第三方 SDK 说明”中补充：

> 我们接入的第三方 SDK/服务包括高德定位 SDK、腾讯 Bugly、腾讯云人脸核验/人脸识别服务、腾讯云 COS、Google ML Kit 人脸检测和俏郎中（QLZ）评估 SDK 等。第三方 SDK 可能因定位、崩溃分析、身份核验、文件上传、蓝牙设备评估等目的处理设备信息、网络信息、位置信息、日志信息、图片/视频、检测设备标识和评估事件等。具体主体、目的、方式和信息范围以提审版本的 SDK 清单、供应商合同和厂商最新披露为准。

## 应用市场提审补充说明

建议在 OPPO、vivo、应用宝后台填写：

> 本次已完成隐私合规整改：1）首次启动展示隐私政策弹窗，提供“同意并继续”和“不同意”两个明确按钮；2）登录页协议勾选框默认未选中，用户必须主动勾选后才能发送验证码或登录，未勾选时仅提示用户勾选，不会自动代勾选；3）应用内新增隐私政策常驻入口，路径为“进入应用 -> 我的 -> 隐私政策”，4 步内可达；4）隐私政策已补充 Android ID、设备 MAC 地址、软件安装列表、剪贴板/剪切板、开机广播恢复提醒、第三方 SDK、设备信息、定位、相机/相册等收集使用目的、方式和范围；5）开机广播仅用于用户已同意隐私政策、已登录且存在未完成服务提醒时恢复提醒，不存在无合理场景自启动。

## 后续复核清单

- 确认线上隐私政策 URL 已发布上述补充内容。
- 确认 App 内弹窗、登录页、我的页常驻入口打开的是同一份隐私政策 URL。
- 提审前清空测试机应用数据，验证首次启动弹窗与登录页默认未勾选状态。
- 使用市场隐私检测报告复核是否仍出现“软件安装列表”“设备 MAC 地址”等 SDK 检测项；如仍出现，按检测报告追加 SDK 名称和信息项。
- 按提审 APK 复核 Google ML Kit、QLZ、腾讯人脸、COS、Bugly 和高德的最新隐私/数据安全披露，不直接复用 2026-05 的厂商清单。
- 由产品/法务确认 QLZ SDK 提供方的完整法定主体名称、隐私政策 URL 和实际处理信息后再发布线上文本。
