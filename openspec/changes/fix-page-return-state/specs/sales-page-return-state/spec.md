## Purpose

保证销售人员在客户列表、客户详情和评估流程之间正常往返时，详情能够显示最新服务端结果，列表能够保留已有筛选和浏览位置。只修复返回后的数据及展示状态，不增加导航框架或网页结果回传协议。

## ADDED Requirements

### Requirement: 客户详情重新显示时刷新

客户详情首次成为当前前台页面及从后续页面返回重新显示时 SHALL 查询该客户的最新详情。刷新 MUST NOT 重建详情页面、覆盖其他客户或结果页的数据，也不依赖网页返回结果关联。

#### Scenario: 评估结束后逐级返回详情
- **WHEN** 用户从客户详情进入评估并完成操作，随后正常返回原客户详情
- **THEN** 查询并显示该客户最新的评估等级、状态和报告入口，不继续把旧缓存当作最新结果

#### Scenario: 查询失败与重试
- **WHEN** 返回详情后的最新查询失败
- **THEN** 显示可重试的错误提示，重试查询当前客户，不跳转其他页面

#### Scenario: 返回途中重复重组
- **WHEN** 页面只发生重组而未重新成为当前前台页面
- **THEN** 不因此重复启动详情查询；已离开客户的迟到响应不覆盖当前客户

### Requirement: 客户列表普通返回保留浏览状态

客户列表在进入详情后普通返回 SHALL 保留搜索条件、已加载分页和滚动位置。仅首次加载或搜索、筛选条件变化时 SHALL 重置分页和滚动位置；已成功加载的空列表也属于有效状态。

#### Scenario: 多页列表返回
- **WHEN** 用户加载多页客户，在较后位置打开详情后返回
- **THEN** 保留此前已加载客户及浏览位置，不自动跳到顶部或用第一页覆盖全部数据

#### Scenario: 修改搜索或筛选
- **WHEN** 用户修改搜索词或筛选条件
- **THEN** 按新条件从第一页查询并回到列表顶部，不混入旧条件的分页数据

#### Scenario: 页面重建与进程恢复
- **WHEN** 页面重建且原列表数据仍保留，或进程恢复后列表数据已不存在
- **THEN** 前者保留有效浏览状态，后者正常重新加载，不因加载标志恢复而永久停留空白

#### Scenario: 空结果与查询失败
- **WHEN** 相同条件此前已成功返回空结果，或首次查询失败
- **THEN** 成功空结果不因普通重组反复查询；失败保持现有错误及用户重试能力，不被当作成功缓存
