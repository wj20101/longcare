## Why

客户登记接口已新增是否残疾和备注字段，客户端尚未提供输入或传递参数。补齐登记链路，让销售人员能够按需填写资料，并保证默认值、确认内容和实际提交一致。

## What Changes

- 登记页增加“是否残疾”是/否单选，默认“否”，提交 `isDisability=0`；选择“是”提交 `1`。
- 增加“备注（选填）”多行输入，不填不阻止继续或提交；沿用现有文本处理约定，提交前去除首尾空白，空值提交空字符串。
- 确认页显示选择结果及已填写备注；备注为空时不展示空白备注行。
- 将两项纳入现有登记草稿保存/恢复及请求映射；提交失败或返回编辑时保留输入，新建登记时恢复默认值。
- 补充参数序列化、提交、单选和草稿恢复测试，不新增表单框架或依赖。

## Capabilities

### New Capabilities

- `customer-registration-fields`：客户登记新增资料的输入、确认、恢复与提交契约。

### Modified Capabilities

无。既有评估、导航和报告能力不变。

## Impact

- `:app` 的销售登记/确认 UI、草稿及其 Saver、字符串资源和测试。
- `:core:model` 的 `AddUserLatentParamModel`，`:core:data` 的请求 DTO、Repository 映射和接口契约测试。
- API 仍为 `POST /V1/Sale/AddUserLatent`，仅补齐已定义的两个请求字段；不改变其他字段、响应处理、照片上传或评估流程。
- 不改客户列表/已登记客户详情展示、Room、权限、SDK、依赖或发布配置。残疾状态和备注可能包含敏感资料，不新增内容日志，不为验证自动提交真实客户数据。
