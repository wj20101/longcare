# login-feature-boundary Specification

## Purpose

建立可由架构守卫和业务回归共同验证的登录功能边界，使页面、协议交互与隐藏校验入口由登录 feature 完整持有，同时保持认证根栈、开放 WebView、平台/厂商能力以及现有用户行为稳定。

## Requirements

### Requirement: 登录功能具有单一页面所有权
工程 SHALL 由登录 feature 持有登录页面、页面专属资源、协议交互、隐藏校验入口和屏幕状态装配；应用壳层 MUST 仅承担认证根导航组装、WebView 跳转以及需要 Activity 或厂商环境的平台适配。质量验证 MUST 阻止登录页面重新出现在 legacy 应用功能目录，也 MUST 阻止登录 feature 反向依赖应用壳层实现。

#### Scenario: 页面边界符合约束
- **WHEN** 维护者运行架构与模块边界验证
- **THEN** 登录页面、协议交互 UI、隐藏校验入口及其专属资源只归属于登录 feature
- **AND** 应用壳层仅通过 feature 的公开入口、不可变配置和显式回调完成组装

#### Scenario: 页面回流应用壳层
- **WHEN** 变更在 legacy 应用功能目录新增登录页面文件，或从登录 feature 引用应用壳层导航、平台实现或资源命名空间
- **THEN** 质量验证 MUST 失败
- **AND** 输出 MUST 指明违规路径与允许的依赖方向

### Requirement: 登录路由与认证根栈契约保持兼容
迁移后系统 SHALL 保持既有类型安全登录 route、认证根栈、登录成功跳转和返回栈所有权；登录 feature MUST 通过应用壳层提供的动作边界报告登录成功或请求外部页面，不得自行持有或操作根导航控制器。

#### Scenario: 登录成功
- **WHEN** 当前登录尝试返回成功状态
- **THEN** 系统通过既有认证根栈契约进入正确的 Home 所有者
- **AND** 同一成功结果不得因普通重组重复创建 Home 目的地

#### Scenario: 登录尚未成功
- **WHEN** 登录处于空闲、提交中或失败状态
- **THEN** 用户保持在登录页面并获得与当前流程等价的进度或错误反馈
- **AND** 系统不得提前修改认证根栈或进入 Home

#### Scenario: 打开协议网页
- **WHEN** 用户点击用户协议或隐私政策
- **THEN** 登录 feature 将完整 URL 和标题请求交给应用壳层的既有 WebView route
- **AND** feature 不得限制 URL host、直接创建 WebView 目的地或修改开放导航策略

### Requirement: 验证码登录与反馈行为保持等价
模块迁移 SHALL 保持手机号输入约束、验证码发送、倒计时、验证码焦点、登录提交、最近登录手机号读取和反馈确认语义，不得改变登录网络接口、用户会话写入或持久化契约。需要用户可见且不可在暂停收集期间丢失的反馈 MUST 保留到活动页面以匹配标识确认消费。

#### Scenario: 已同意协议后发送验证码
- **WHEN** 用户输入有效手机号、已同意协议并请求验证码
- **THEN** 系统调用既有验证码发送流程并显示当前发送/倒计时状态
- **AND** 发送成功后验证码输入框获得焦点

#### Scenario: 已同意协议后提交登录
- **WHEN** 用户输入有效手机号和验证码、已同意协议并提交登录
- **THEN** 系统调用既有登录流程且沿用当前网络与会话契约
- **AND** 提交期间的进度、失败反馈和重试可用性与迁移前等价

#### Scenario: 页面暂时停止收集反馈
- **WHEN** 登录流程产生反馈后页面暂时进入非活动生命周期并随后恢复
- **THEN** 尚未确认消费的反馈仍可展示
- **AND** 使用不匹配标识或已确认的反馈不得被错误清除或重复展示

### Requirement: 协议同意与链接选择保持现有语义
系统 SHALL 在发送验证码或提交登录前要求用户同意用户协议与隐私政策；未同意时 MUST 显示既有确认弹窗且不得调用验证码或登录接口。用户协议 SHALL 优先使用服务端返回的非空动态地址并在缺失时使用应用壳层注入的兜底地址；隐私政策 SHALL 使用应用壳层注入的现有地址，不得因模块迁移复制或改变全局协议来源。

#### Scenario: 未同意协议时请求业务操作
- **WHEN** 用户未勾选协议并点击发送验证码或登录
- **THEN** 页面显示协议确认弹窗且不调用对应网络流程
- **AND** 用户确认后仅更新同意状态，不自动重放此前操作

#### Scenario: 用户取消协议确认
- **WHEN** 用户在协议确认弹窗选择取消或关闭
- **THEN** 页面保持未同意状态并停留在登录页
- **AND** 验证码和登录流程均不会启动

#### Scenario: 服务端提供用户协议地址
- **WHEN** 启动配置包含非空用户协议 URL 且用户点击用户协议
- **THEN** 系统打开该动态 URL
- **AND** 不使用兜底用户协议地址覆盖它

#### Scenario: 服务端用户协议地址不可用
- **WHEN** 启动配置尚未成功或用户协议 URL 为空
- **THEN** 系统打开应用壳层注入的现有兜底用户协议 URL
- **AND** 隐私政策仍可通过其现有兜底 URL 打开

### Requirement: 隐藏校验入口在生产构建中保持可达且受控
登录主标识的既有长按操作 SHALL 在 Debug 和 Release 共享源码中继续打开隐藏校验入口；相机校验、备用人脸、手动人脸、正式人脸校验与 NFC 校验 MUST 均通过应用壳层提供的动作回调启动。登录 feature MUST NOT 直接构造 `Intent`、引用校验 Activity、持有 `Activity`，或绕过现有组件导出与生产发布守卫。

#### Scenario: 长按打开隐藏校验入口
- **WHEN** 用户在 Debug 或 Release 构建中长按登录页主标识
- **THEN** 页面显示包含五个既有校验选项的入口面板
- **AND** 普通点击或普通页面重组不会误打开该面板

#### Scenario: 选择任一校验入口
- **WHEN** 用户选择相机、备用人脸、手动人脸、正式人脸或 NFC 校验项
- **THEN** 面板关闭并只调用对应的一次应用壳层动作
- **AND** 登录 feature 不直接启动 route、Activity 或厂商 SDK UI

#### Scenario: Release 校验边界被移除或仅限调试
- **WHEN** 变更删除长按入口、用调试条件包裹入口，或使任一平台动作由 feature 直接执行
- **THEN** Release 与架构质量验证 MUST 失败
- **AND** 既有组件非导出策略和生产 fail-closed 门禁 MUST 保持不变
