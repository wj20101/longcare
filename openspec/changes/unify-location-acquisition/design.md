## Context

动机见 [proposal.md](proposal.md)。本设计基于 2026-09-29 的 `cc89ecc5` 静态检查，尚未完成现场漂移复现，也未确认事故设备与连接设备是否相同。

当前实现事实：

- `ContinuousAmapLocationManager` 使用高德 11.2.100；经纬度由 `Double` 转字符串上传，未发现精度截断、重复坐标转换或累计距离上传。
- `DefaultLocationFacade.getCurrentLocation` 优先使用 5 分钟缓存，否则快速定位最多 4 秒；`getFreshLocation` 独立定位默认 10 秒。两套单次配置相近，页面进入与碰卡会重复请求。
- 持续定位默认 30 秒间隔、20 秒超时，SDK 定位缓存未显式关闭。`LocationSampleStore` 先记录样本，`LocationSampleEvaluator` 之后仅校验范围与时间；跳点只诊断，不阻止上传。
- `SharedOrderDetailViewModel` 定位失败仍以空字符串调用开始服务。`SalesViewModel` 再次定位失败保留旧 `currentLocation`，登记提交也未统一校验时间。
- `CameraViewModel` 使用缓存优先入口；相机恢复逻辑允许精确或大致权限，水印状态只有坐标字符串，不足以在拍摄时判断新鲜度。
- 已有唯一持续采集/上传入口、会话失效和显式恢复契约，见 [系统概览](../../../docs/architecture/system-overview.md#定位会话与生命周期)。这些是需要保留的安全约束，不是冗余。
- Release 普通定位诊断没有形成可查询的质量证据。截图坐标能复算约 3.8/6 公里距离，但缺少提供方来源、精度与完整中间轨迹，不能据此断言根因。

用户已明确修订职责边界：客户端只负责定位获取、质量和生命周期；签到/结单距离由服务端判断。不再等待服务端业务半径，不实施位移/速度拦截或跳点确认算法。在线 [Swagger JSON](https://careapi.ytone.cn/swagger/v1/swagger.json) 可读取，但未定义业务半径和坐标系；这不构成定位入口收敛和冗余清理的阻塞条件。

## Goals / Non-Goals

**Goals:**

- 只有一个单次业务入口、一套结果与质量判定；持续采集与单次获取生命周期隔离。
- 一次迁移实际调用方并删除旧路径，减少缓存、超时和错误兜底分支。
- 识别样本失效与定位元数据质量不足，如实传递质量合格的真实样本；不以距离推断准确性，不以静止锁点、虚构坐标或大量静默丢点制造正常假象。

**Non-Goals:**

- 不承诺消除所有物理环境与第三方定位误差，不以本次代码重构替代本地真机准确性核验。
- 按用户收敛后的范围，不进行服务端数据对照，不扩展 Bugly 或其他线上定位诊断，不将两者作为本轮完成条件。
- 不创建定位框架、可插拔策略工厂、持久轨迹库或后台自动重启机制，不同时升级 SDK。
- 不计算距客户距离，不依据相邻点位移或推算速度拦截，不建立跳点候选和确认窗口，不在客户端复制服务端签到/结单规则。
- 不改导航、护理订单状态规则、QLZ 定位权限、接口字段或客户历史坐标；不清理无关模块和历史 OpenSpec 归档。

## Decisions

### 1. 在现有模块内收敛职责

`LocationFacade` 保留一个单次获取方法，返回 Android-free 的成功样本或可区分的失败原因；调用方不能自定 SDK 配置与超时。原 `getCurrentLocation`/`getFreshLocation` 合为一个新契约，全部调用方同一切片迁移，不保留 deprecated 包装。保活控制仍按原有 owner 契约使用，不为接口整洁额外搬迁架构。

`:feature:location` 内统一 SDK 映射与纯 Kotlin 校验，`:core:model`/`:core:domain` 只包含稳定契约，不向 UI 泄漏高德类型。SDK 原始结果在边界复制为不可变样本，避免持有可变回调对象。

持续定位由现有 Service 独占收集。单次定位使用独立临时客户端，终止时只释放自身。拒绝强制共用一个可变 SDK 客户端：单次模式、超时和停止操作会增加持续采集的耦合。

同一页面或业务动作在处理中禁止重复触发；单次入口采用一个有界在途请求槽，冲突返回明确处理中状态，不排长队、不跨业务共享成功结果。取消只释放所属请求，连续定位不受影响。持续定位不因坐标变化而启动额外单次请求。

### 2. 显式配置与有限等待

统一基础配置：`Hight_Accuracy`、不返回地址、不允许模拟、开启 SDK Wi-Fi 扫描请求，显式关闭定位缓存，不启用加速缓存回调。单次仍使用最新定位策略，总预算 15 秒；持续采集保留 30 秒间隔和 20 秒 SDK 超时。

每次单次 SDK 结果若不合格，可在剩余预算内最多再请求一次，不延长 15 秒总等待；权限或鉴权错误直接结束。采集时间与接收时间分别保存；超时、请求代次和等待使用单调时钟。采样时间缺失不回填成有效“当前时间”。不得自行刷新时间来通过新鲜度校验。

只保留当前请求/会话所需样本，不保留供业务快捷回退的全局位置缓存。重复坐标不等于重复采样：静止时相同坐标但新的真实采样仍可有效；反之新回调不证明内部数据新鲜。

配置依据：高德 [定位指南](https://lbs.amap.com/api/android-location-sdk/guide/android-location/getlocation)、[配置 API](https://a.amap.com/lbs/static/unzip/Android_Location_Doc/com/amap/api/location/AMapLocationClientOption.html)。高精度不是 GPS-only；关闭地址不改变坐标精度；一次最新结果也不是绝对真值。SDK 缓存开关与其他历史位置机制不可混同，最终仍校验返回元数据。

### 3. 校验先于业务发布与上传

统一校验有限经纬度、采集时间、顺序、新鲜度、精度是否存在且有效、来源/可信度、模拟标记、坐标系。高德枚举语义见 [结果 API](https://a.amap.com/lbs/static/unzip/Android_Location_Doc/com/amap/api/location/AMapLocation.html)。不能只以来源为基站就全部拒绝，也不能仅凭 GPS 或小 accuracy 就认定准确。accuracy 表示提供方报告的误差估计，不是距客户距离；质量规则依据 SDK 语义和测试制定，不从业务半径推导，不自行加入未经确认的固定米数拦截。

业务当前定位要求精确权限；照片只有大致权限时可继续拍照，但不写入当作有效精确位置的数字水印。核对 SDK 输出到现有接口请求参数的本地传递，保持经纬度顺序及精度、不新增转换；不处理历史客户坐标，不进行服务端数据对照。

未通过质量校验的样本不进入业务有效样本，也不保存为待确认位置。上传等待期间样本可能过期，实际发出请求前重新核对会话和样本有效性，不只在 SDK 回调时检查。

### 4. 持续采集只执行样本质量规则

每个持续样本通过质量校验后进入现有上传流程，不计算它与客户或上一点的距离，也不要求后续点为它确认。仅保留时间顺序、会话隔离和实时分发确实需要的状态，不维护前一坐标、位移、速度或跳点候选。

删除现有 `maybeTrackJump`、球面距离/推算速度计算以及仅服务这些计算的常量、状态和事件字段；不将它们移入新的诊断包装保留。验收人员可在受控测试中比较实际位置与采集坐标，但该分析不进入 App 运行时的拦截逻辑。

无有效样本时保留缺口，正常采集继续；新样本满足质量规则即可恢复，不锁定首次位置、不平滑或虚构坐标、不重复提交旧位置。UI/通知表达降级状态但不高频弹 Toast、不停止真实护理业务。服务端返回距离不满足要求时按业务接口结果提示，不调整坐标绕过校验。

### 5. 业务消费差异只保留必需部分

| 调用方 | 迁移后的规则 |
|---|---|
| NFC 核验/绑定/签退 | 碰卡时获取一次；取消或失败留在现有步骤；确认绑定或提交前校验时效，失效则重新获取并确认 |
| 开始服务 | 用统一入口，失败不再提交空经纬度；开始成功后按既有流程启动持续采集 |
| 持续上报 | 校验合格才送唯一上传入口；会话代次、取消、无补传契约保持 |
| 客户登记 | 开始重新定位时失效旧的可提交状态；失败不能复用旧值；提交前校验坐标来源与时效，延续位置可选规则 |
| 照片水印 | 状态保留采集时间等必要元数据；拍摄时检查而非只在 ON_RESUME 检查，失效则重新获取或明确未获取，不禁止无位置拍照 |

销售照片/登记路由携带的坐标也要追踪来源；不能把只有经纬度的路由参数重新构造为“刚获取”的当前定位。服务端客户参考坐标与本机当前位置分开，不统一成一个缓存字段。

失败原因用少量稳定类型表达：权限不足、定位开关关闭、处理中、超时、质量不足、网络获取失败、SDK 配置/其他失败。取消继续抛 `CancellationException`，不转成错误 Toast。业务接口拒绝沿用接口错误信息处理，不归并成定位失败。

### 6. 生命周期与权限不扩权

精确/大致权限成对申请，关键入口要求精确授权；永久拒绝有设置恢复路径。恢复时重查系统开关和权限，不沿用旧授权布尔值。

前台 Service 仅在平台允许的可见业务流程启动；异步订单确认返回时已进后台则等待用户回到订单页重试。已合法启动的服务保持前后台连续采集，不新增后台定位权限或定时重启。依据 [Android 前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)；[Wi-Fi 扫描限制](https://developer.android.com/develop/connectivity/wifi/wifi-scan)意味着 30 秒定位不保证每次全新扫描。

保留现有停止、换号、Token 失效、Service 代次保护与幂等释放。停止后不可发新请求；已经发到服务端的请求无法撤回，仍需要服务端核验订单。进程结束不补报、重启不自动恢复旧单。

### 7. 仅做本地核验

保留既有 `LocationEventTracker`，不新增正式版质量摘要上报，不打开全局 Release DEBUG 日志，不把每个拒绝点作为异常上传，不建立诊断队列。此前新增线上诊断的待确认问题随本次范围收敛撤回，不再等待批准。

本地自动化核验 SDK 回调映射、原始时间、经纬度顺序和数值精度、提交前时效及生命周期；使用替身仓库确认请求参数，不写入真实业务数据。真机验证本机采集的静置表现、真实移动和权限/网络恢复，不依赖服务端查询。

原始坐标仅用于受控本地测试，不进入默认日志、线上诊断或 Git。接口不新增质量字段，服务端业务距离判断保持原状。本机采集出现异常时继续排查客户端与 SDK 配置，不以新增服务端对照替代本地工作。

### 8. 定位相关冗余清理清单

| 对象 | 删除依据与替代 | 必须保留的边界 |
|---|---|---|
| quick/fresh 方法、两套 option builder 和超时常量 | 全部调用方迁至唯一单次契约后删除 | 单次与持续的 SDK 生命周期隔离 |
| NFC 入页预定位与专用 preparing 状态 | 删除预定位后无消费者，连同专用 effect/参数一起移除 | 实际碰卡 Loading、防重复提交与权限恢复 |
| `getCachedLocation`、5 分钟缓存、`TimedLocation` 等缓存读写 | 当前公开缓存接口无生产调用；迁移后业务不消费缓存 | 实时分发与会话内判断所需最近有效样本，不能整类盲删 |
| 跳点诊断、球面距离/推算速度计算、前一坐标及专用阈值/事件字段 | 客户端不承担距离判断，删除仅服务此逻辑的状态与测试 | 样本时序、元数据质量及现有会话有效性校验 |
| 旧 provider 标签及重复可空失败包装 | 唯一单次来源和分类失败替代，搜索调用与诊断消费后删除 | 必需的场景诊断及对外 API 契约 |
| 空坐标兜底、重新定位失败仍可提交旧坐标 | 新业务规则替代 | 登记可选位置与无位置照片能力 |
| 强绑旧方法名/源码字符串的测试 | 以执行型契约、取消和时序测试替换后删除旧断言 | 架构边界与资源释放回归，不为通过测试削减覆盖 |
| 失效字符串资源、导入、注释和当前文档段落 | 全仓引用、编译、资源检查确认无消费者后删除/替换 | 历史归档、无关资源、原始迁移记录不批量删除 |

无“以后可能用”的空壳、兼容代理或新旧开关。依赖没有确认变为无用前不删除；本次默认不变更依赖。具体文件级删除清单在实现 diff 中核对，不提前删除尚有消费者的文件。

### 9. 参数定稿与交付边界

区分采集质量参数与现场验收指标，不再以服务端业务距离作为参数依据：

1. 依据当前 SDK 文档与真实返回语义明确时间、新鲜度、精度有效性、来源/可信度及模拟标记规则，补齐边界测试；不向用户索取签到/结单半径来决定是否实施。需要额外固定精度上限时必须提供测试依据并单独确认，不能假借“准确”添加任意米数限制。
2. 核对设备/版本，通过 Release 多次独立定位确认请求正常结束、失败后可恢复及退出后无活动监听残留；结合自动化证明取消、时效与会话隔离，不制定跳点触发、速度阈值或坐标确认算法。
3. 按用户 2026-09-29 的收尾决定，取消长时漂移和功耗专项，不要求提交前先制定整套偏差/功耗阈值。多次定位记录全部尝试的结果，不只统计成功请求；结果只能证明已测获取流程，不能推导所有环境的绝对定位准确性。

已定配置为单次总预算 15 秒、持续 30 秒间隔和 20 秒 SDK 超时；它们不代表精度或成功率承诺。未知的服务端半径或尚未安排的现场验收不阻止统一入口与清理实施，但没有测试证据时不能标记发布验收或漂移根因已闭环。

实施规则定稿：`LocationQuality` 以提供方采样时间、接收墙钟与接收单调时间校验总年龄 ≤15 秒；15 秒来自高德 HIGH 的环境信息新鲜度定义，不是业务半径或误差米数。缺失时间、未来时间、墙钟回拨至接收前、单调时间倒退均拒绝，不刷新原采样时间。持续会话拒绝会话前和不晚于已处理时间的点；相同坐标的新采样不视为重复。精度要求有限且 >0，不设置米数上限。来源接受 SDK 常量值 1/2/5/6/7/12，拒绝缓存/离线/最后位置/大致/未知来源；可信度要求 HIGH(1)、非模拟、非最后位置、GCJ02。这些值按 11.2.100 JAR 常量及上文官方文档核对，室内可用率仍须现场确认。

路由只携带登记本次样本（含原始元数据），不能把客户参考坐标或只有经纬度的路由参数还原成新样本。SDK 创建的隐私初始化统一放在同一个小型创建边界，单次和持续各自创建实例，用可控客户端回调测试注销/停止/销毁，不引入策略工厂或业务缓存。

现有普通定位事件只写 Debug 日志，正式版既有 Bugly 异常通道保持不变；不扩展其用途，不要求线上事件可查询性作为本轮验收。

## Risks / Trade-offs

- [严格校验可能使室内定位可用率下降] → 同时衡量精度与缺口；失败可恢复，不扩大服务端半径或静默放行。
- [高德连续返回自报高精度但实际错误的位置] → 客户端元数据无法独立证明真实位置；保留受控源头对照，必要时提交厂商，不追加距离过滤掩盖问题，也不宣称保证绝对准确。
- [关闭 SDK 缓存可能增加等待或耗电] → 保持现有持续频率和单次 15 秒预算，检查多次请求的完成情况；本次不增加功耗专项或经验性阈值。
- [多调用方迁移遗漏路由或水印持有的旧值] → 覆盖销售路由、确认等待、拍摄时检查，而不只替换接口名称。
- [取消与会话切换竞态导致跨账号/跨订单结果] → 保留代次保护、取消透传和唯一上传入口，加入迟到回调及在途请求测试。
- [真机覆盖有限] → 以 Pixel 10 的多次定位及权限/生命周期结果说明已测范围，不将自动化或短时结果泛化到所有设备环境；服务端对照、长时漂移和功耗专项不在本轮范围。

## Migration Plan

1. 完成参数/接口事实核对与可执行基线测试；记录规则定稿到本 design/specs，而非新增执行日志。
2. 在独立可编译切片中统一单次契约并迁移全部生产调用方，同步删除旧路径；不发布新旧混用的中间状态。
3. 落地统一质量校验和业务提示，移除原有跳点距离诊断，保留既有订单生命周期与诊断边界；每组执行 focused tests。
