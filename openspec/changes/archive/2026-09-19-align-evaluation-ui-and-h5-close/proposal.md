## Why

现有 QLZ 自定义检测页与用户提供的三张蓝湖设计稿不一致，且评估 H5 尚无统一关闭回调。需要在保留现有设备检测和 Navigation 3 返回链路的基础上，统一视觉与 H5 容器退出行为。

## What Changes

- 按「检测」「检测-2」「检测3」实现握持提示、五指握持完成倒计时、沙漏检测进度三种展示状态，统一蓝色渐变、白色圆角卡片、标题和素材。
- 五指灯、进度仍来自真实 SDK 状态；倒计时仅用于准备展示，不驱动或伪造设备检测、完成或上传。
- 所有应用内 H5（表单、报告、普通网页、协议及隐私弹窗）统一提供 `window.NativeBridge.closeWebView()`；收到合法调用后仅返回当前 H5 的上一页或关闭当前网页弹窗，不关闭 Activity、不清空首页、不推断提交成功或同意隐私协议。
- 移除表单专用路由标记和动作；桥接仍限定入口 HTTPS 来源，防止跨源页面、子框架及失效页面调用。隐私网页开启 JavaScript 并复用通用容器。
- 删除被新展示替代且已确认无引用的旧 UI、文案和素材，不清理其他功能。
- 按用户追加确认，补齐通用网页与隐私政策弹窗的渲染进程退出处理：显示异常提示并释放失效 WebView，保留原生返回和原有隐私同意流程；不放宽新增 WebKit 检查。

## Capabilities

### New Capabilities

- `evaluation-design-presentation`: 三张设计稿对应的检测展示、真实状态映射和异常恢复。
- `evaluation-h5-close`: 评估 H5 单一关闭契约、来源限制和 Navigation 3 生命周期安全。

### Modified Capabilities

无。主 specs 尚未覆盖这两个增量能力；不回填旧检测规格，也不改写未归档的其他 change。

## Impact

- 修改 `:app` 销售检测 UI、资源、检测展示状态和 WebView 容器/路由；必要的页面用途动作契约涉及 `:feature:home`。
- 预计增加 AndroidX WebKit 依赖，用于来源受限的消息桥和文档起始脚本；实施时先核对稳定版本与运行时能力。
- 不修改服务端 API、数据库、QLZ AAR、导航框架、助手 APK 或生产发布门禁。
- 兼容边界：只采用 Navigation 3；所有 H5 入口共用关闭桥，不新增旧 JS 方法别名。保留 HTTPS 和 WebView 能力要求，不使用不安全兼容桥。
- 风险与外部依赖：设计素材需从蓝湖取得；SDK 未提供倒计时回调，须核对 Demo/AAR 事件顺序；真实 H5 的 HTTPS 来源/重定向与 WebView 能力须核实，不能用全域白名单兜底。Mock 可验证展示和关闭行为，但不能替代真实 BLE/H5 联调。
