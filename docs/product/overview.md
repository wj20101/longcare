# LongCare 产品概览

最后核对：2026-08-29

## 产品定位

LongCare 是面向长期护理服务执行和客户评估场景的 Android 客户端。应用把登录、订单执行、身份核验、定位、服务照片、计时、NFC 签到签退，以及销售顾问的客户登记和评估流程放在同一套受会话与权限约束的移动端工作流中。

当前产品主链路已经实现。现阶段的主要工作不是补齐基础功能，而是保证生产发布安全、提高关键流程验证深度，并继续把仍位于 `:app` 的业务实现迁入独立 feature。

## 用户角色

| 角色 | 应用入口 | 主要目标 |
|---|---|---|
| 护理服务执行人员 | 普通账号首页 | 查看服务单、完成签到与身份核验、执行护理项目、留存位置和照片、结束服务 |
| 销售顾问 | `userIdentity == 2` 的销售首页 | 管理潜在客户、登记资料与照片、处理提醒、发起表单或设备评估、查看报告 |
| 运营与项目人员 | 使用服务端和客户端留痕结果 | 确保服务过程完整、可追溯，并降低人工补录和异常排查成本 |

账号角色由登录后的用户资料决定，同一安装包在 `HomeRoute` 内选择护理端或销售端体验。

## 核心流程

### 启动、隐私与登录

1. 首次启动先展示隐私同意弹窗；引入用户隔离存储的升级也会清除旧授权状态并重新展示，未同意时不生成安装 GUID，也不继续初始化业务 SDK。
2. 登录页协议默认未勾选，发送验证码和登录都要求用户主动同意。
3. 会话状态决定启动目的地：未解析时显示启动页，已登录进入首页，未登录进入登录页；冷切换不迁移旧账号，用户需要重新登录。
4. 登录成功后先建立该复合账号的独立存储，再从服务端重新拉取系统配置和初始订单；失败显示可重试状态，不读取旧账号或旧版本值。
5. 首页进入时异步记录设备和网络环境日志；会话失效由全局流程统一退出登录并提示。
6. 启动更新检查由 WorkManager 持久化，发现新版本后显示应用内更新弹窗。

### 护理服务执行

典型链路由首页、服务计划/记录列表和订单详情发起，并按订单状态串联以下能力：

1. 选择服务单或护理项目。
2. 通过原生 NFC 或支持的外接读卡器完成开始/结束服务所需的读卡流程。
3. 进入身份核验：
   - 服务端已有服务人员登记照时，进入 CameraX + ML Kit 页面，完成单人、姿态和眨眼活体检查后拍照，并调用 `/V1/User/CheckFace` 比对。
   - 服务端没有登记照或查询失败时，进入补录流程并清理旧版遗留的本地人脸文件。
   - 长者留痕照片继续使用标准带水印相机流程。
4. 选择本次服务内容，进入倒计时；服务进行期间按需采集和上报位置、拍摄并上传阶段照片。
5. 选择结束方式、完成签退和服务结果确认，随后回到首页。

具体页面与路由以[页面与路由地图](../architecture/ui-and-screen-map.md)为准。

### 销售客户与评估

销售账号在首页内使用独立的首页、客户和个人中心导航：

1. 查看最新客户和待办提醒，搜索或选择潜在客户。
2. 登记客户信息；最多添加三张相机照片，复用标准相机、水印、预览和受管文件生命周期。
3. 表单评估使用服务端返回的 `pgUrl`，在应用内 WebView 打开。
4. 设备自动评估先从 LongCare 服务端获取一次性 Token，再请求蓝牙权限并打开 QLZ SDK 页面。
5. SDK 完成后重新查询客户详情，报告仍使用服务端返回的 `pgUrl` 在应用内打开。

完整接入约束见 [QLZ SDK 接入](../integrations/qlz-sdk.md)。

## 关键产品规则

- “服务单”是护理服务订单/执行对象，文档中不混用“工单”或“任务单”。
- 标准业务照片只提供应用内相机采集，不提供相册选择；照片经过方向修正、水印、压缩、大小校验和受管文件清理。
- 服务照片上限来自系统配置；缺失或异常配置使用代码中的安全回退策略。
- 持续定位只在当前订单进行中运行。单点上传失败不落库、不排队、不补传；登出、换号、订单成功结束或任务被移除时停止。
- 人脸采集要求单人、合格姿态和完整眨眼序列；最终是否通过由服务端订单比对结果决定。
- 销售登记照片在删除、替换、放弃或提交成功后释放；提交失败时保留以便重试。
- QLZ 的 `appSecret` 只允许存在服务端，Android 客户端只接收一次性检测 Token。
- 同一设备上的复合账号使用独立本地业务空间；正常退出不会删除可复用的该账号订单、配置和持久文件，但会清理会话秘密、临时文件和旧 epoch 后台任务。
- 协议、隐私政策、销售表单和报告 WebView 不按业务 host 设置白名单，合法 HTTPS 跨域跳转可继续打开；HTTP 是否可用仍服从 Android 应用级明文策略，失败时提供重试而不放宽全局安全配置。
- 登录页长按 Logo 打开的“功能验证”面板是内部验证入口，不属于普通用户产品导航；Release 中相关 Activity 均不可导出。

## 当前产品边界与风险

- 未发现缺失的核心护理或销售主链路；仍需通过真机、集成和 smoke 验证降低跨权限、NFC、定位、相机和进程恢复的回归风险。
- 应用自有 Activity 当前按产品要求锁定竖屏，并在 targetSdk 36 使用 Activity 级兼容属性保留大屏限制；Android API 37 将取消该退路，因此这是有期限的产品/适配决策。
- 生产发布会因 QLZ 1.3.0.2 的弱 TLS 实现、临时测试配置，以及当前腾讯人脸 ARM64 二进制的 16 KB 对齐问题失败。不得把验收包标记为生产包。
- 大量 route-bound UI 仍在 `:app`，这是维护成本问题，不代表当前用户流程不可用。

开放问题和优先级见[路线图与开放问题](../architecture/roadmap-and-open-gaps.md)。
