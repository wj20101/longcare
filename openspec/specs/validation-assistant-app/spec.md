# validation-assistant-app Specification

## Purpose

为研发与验收人员提供可独立安装、可直接启动且不污染正式应用入口的设备与业务能力验证工具，并保持现有五项真实验证链路可用。

## Acceptance Scope

本次变更的助手真机验收仅要求手机 NFC 功能正常：实际标签读取、重复读取一致性、结果复制、NFC 开关与设置返回恢复，以及前后台/返回和 Activity 重建时的监听管理。NFC 验收无需真实登录，不以模拟标签替代真实贴卡证据。

R65C、拍照、默认人脸、备用腾讯人脸、手动人脸及真实登录排除在本次真机验收与任务完成门槛之外；未验收不代表已通过。下述非 NFC 行为契约、已有入口和实现继续保留，此范围调整不删除功能，也不豁免双应用隔离、安全要求、构建与正式业务回归。后续需要保证非 NFC 真实链路时另行验收，不以本次 NFC 结果替代。

## Requirements

### Requirement: 助手应用提供独立验证入口
系统 SHALL 提供一个具有独立应用身份的助手应用，用户从系统 Launcher 启动后 SHALL 直接看到功能验证首页，而无需通过正式应用登录页的隐藏手势进入。

#### Scenario: 从 Launcher 打开助手
- **WHEN** 用户点击助手应用图标
- **THEN** 系统打开功能验证首页
- **THEN** 首页展示正式服务人脸验证、手机 NFC / R65C 读卡验证、拍照验证、备用人脸验证和手动人脸采集验证五个入口

#### Scenario: 助手与正式应用共存
- **GIVEN** 设备已安装正式应用
- **WHEN** 用户安装助手应用
- **THEN** 两个应用均保留各自的 Launcher 图标并可独立启动

### Requirement: 助手保留五项验证能力
助手应用 SHALL 保留原功能验证面板的五项能力，并 SHALL 使用与正式业务相同的生产能力或公共业务实现进行验证，而不是维护一套行为不同的伪实现。

#### Scenario: 验证正式服务人脸流程
- **GIVEN** 助手内已有有效登录会话
- **WHEN** 用户输入受支持的订单 ID 并进入正式服务人脸验证
- **THEN** 系统使用真实服务接口和正式人脸采集/比对流程完成验证
- **THEN** 系统展示最终 JPEG 的像素尺寸与压缩后字节数

#### Scenario: 拒绝无效订单 ID
- **WHEN** 用户提交空值、非正整数或超出接口支持范围的订单 ID
- **THEN** 系统留在输入页并显示可理解的校验错误
- **THEN** 系统不发起人脸验证请求

#### Scenario: 验证手机 NFC
- **GIVEN** 设备支持 NFC
- **WHEN** 用户进入读卡验证并贴近受支持的标签
- **THEN** 系统在页面可见期间启用前台 NFC 读取并展示读取结果
- **THEN** 用户离开页面后系统停止该验证会话并释放监听资源

#### Scenario: 验证 R65C 外接读卡器
- **GIVEN** 设备不支持手机 NFC 或当前验证路径选择外接读卡输入
- **WHEN** R65C 以 HID 键盘事件输入卡号并结束一次扫描
- **THEN** 系统展示原始输入、规范化 UID、完成时间和成功或失败状态
- **THEN** 用户可以清空、重新聚焦或复制有效 UID

#### Scenario: 验证拍照流程
- **WHEN** 用户进入拍照验证并授予相机权限后完成拍照
- **THEN** 系统使用正式业务的拍照、水印、压缩和预览能力返回结果

#### Scenario: 验证两种兼容人脸采集路径
- **WHEN** 用户分别进入备用腾讯人脸验证或手动人脸采集验证
- **THEN** 系统启动对应的正式兼容能力并允许用户完成或取消流程

### Requirement: 助手会话与正式应用隔离
助手应用 MUST 在自己的应用沙箱内管理登录状态和本地数据，MUST NOT 读取、覆盖或依赖正式应用的私有会话；需要服务端鉴权的流程 SHALL 在助手内完成鉴权。

#### Scenario: 未登录时选择鉴权验证
- **GIVEN** 助手内没有有效会话
- **WHEN** 用户选择需要真实服务鉴权的人脸验证
- **THEN** 系统引导用户在助手内登录
- **THEN** 登录成功后系统返回并继续原先选择的验证流程

#### Scenario: 助手登录不影响正式应用
- **WHEN** 用户在助手内登录、退出或清除助手数据
- **THEN** 正式应用的登录状态和私有数据保持不变

#### Scenario: 会话失效
- **GIVEN** 助手内会话已被服务端判定失效
- **WHEN** 鉴权验证收到会话失效响应
- **THEN** 助手清除自身失效会话并要求重新登录
- **THEN** 正式应用会话不受影响

### Requirement: 权限与硬件状态可恢复
助手应用 SHALL 只请求所选验证流程必需的运行时权限，并 SHALL 对拒绝、系统功能关闭和从设置页返回提供可恢复状态。

#### Scenario: 相机权限被拒绝
- **WHEN** 用户拒绝相机权限
- **THEN** 系统不启动相机并说明该验证为何需要权限
- **THEN** 用户可在授权后重新发起验证

#### Scenario: NFC 已关闭
- **GIVEN** 设备支持 NFC 但系统 NFC 开关关闭
- **WHEN** 用户进入读卡验证
- **THEN** 系统显示 NFC 未开启状态并提供进入系统设置的操作
- **THEN** 用户从设置返回后页面重新检查并更新状态

### Requirement: 验证流程返回助手首页
助手应用 SHALL 为每项验证提供一致的取消或返回路径，流程结束后 SHALL 回到助手验证首页，且不得意外进入正式应用的业务导航图。

#### Scenario: 取消验证
- **WHEN** 用户在任一验证流程中执行返回或取消
- **THEN** 系统释放该流程持有的相机、NFC、输入监听或厂商 SDK 资源
- **THEN** 系统返回助手验证首页或其直接上一级页面
