## Purpose

明确本轮已经由用户接受的厂商风险在正式构建中的报告行为，并保留其余发布检查与混淆产物验收要求，区分允许构建、实际验证通过和已知风险消除，避免静默隐藏风险或使用 Debug 结果替代正式包证据。

## ADDED Requirements

### Requirement: 已接受的厂商事项非阻断报告
正式构建 SHALL 允许当前固定 QLZ 测试 key、测试模式、QLZ 1.3.0.5 弱 TLS 及腾讯人脸 6.6.2 已知 16 KB/consumer rules 问题继续存在，并 MUST 输出不含凭据的风险警告，不将其报告为已修复。

#### Scenario: 当前配置构建正式包
- **WHEN** 当前已接受配置进入 production 构建且其余检查通过
- **THEN** 上述事项以警告报告，不单独令构建失败
- **THEN** 报告说明测试配置仍保留、厂商风险尚未修复

### Requirement: 其余发布检查保持阻断
系统 MUST 保留正式签名、模式合法性、编译、Lint allowlist、导出组件及 APK 隔离检查，不得将已接受事项扩展为任意错误的忽略策略。

#### Scenario: 其他检查失败
- **WHEN** 签名缺失、production 与 acceptance 同时启用、检查输入缺失或出现未允许的 Lint 问题
- **THEN** 对应检查返回失败，不能发布成功报告

### Requirement: 实际混淆包验收有可追溯证据
交付 MUST 记录最终提交、正式 APK 哈希、签名、R8 开启状态、设备和具体测试结果；MUST 区分已覆盖与未覆盖路径，不以构建成功证明所有业务或设备无崩溃。

#### Scenario: 正式包验证完成
- **WHEN** 最终 production APK 完成混淆专项及业务烟测
- **THEN** 交付列出实际执行的流程和结果，保留未验证事项与已接受厂商风险
- **THEN** 无测试、跳过、崩溃或失败不得被登记为通过
